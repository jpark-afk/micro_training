{\itshape \doxylink{group__DDSDocGuideModule_a_st_interface}{\texorpdfstring{$<$}{<}\texorpdfstring{$<$}{<}interface\texorpdfstring{$>$}{>}\texorpdfstring{$>$}{>}}}  {\itshape \doxylink{group__DDSDocGuideModule_a_st_cert}{\texorpdfstring{$<$}{<}\texorpdfstring{$<$}{<}cert\texorpdfstring{$>$}{>}\texorpdfstring{$>$}{>}}}  Allows an application to wait until one or more of the attached \doxylink{group__DDSConditionsModule_ga1c45ab3d5584bb3332e98266dc3f7d3d}{DDS\+\_\+\+Condition} objects has a {\ttfamily trigger\+\_\+value} of \doxylink{group__DDSCdrTypesModule_ga02f257a405ea7ff6774cdf4330a7eeb7}{DDS\+\_\+\+BOOLEAN\+\_\+\+TRUE} or else until the timeout expires. 

\hypertarget{group__DDSConditionsModule_WaitSet_usage}{}\doxysubsubsubsubsection{\texorpdfstring{Usage}{Usage}}\label{group__DDSConditionsModule_WaitSet_usage}
\doxylink{group__DDSConditionsModule_ga1c45ab3d5584bb3332e98266dc3f7d3d}{DDS\+\_\+\+Condition} (s) (in conjunction with wait-\/sets) provide an alternative mechanism to allow the middleware to communicate communication status changes (including arrival of data) to the application. 

This mechanism is wait-\/based. Its general use pattern is as follows\+: 

\begin{DoxyItemize}
\item The application indicates which relevant information it wants to get by creating \doxylink{group__DDSConditionsModule_ga1c45ab3d5584bb3332e98266dc3f7d3d}{DDS\+\_\+\+Condition} objects (\doxylink{group__DDSConditionsModule_gab365a205f11e5da37e380ef825c74ecd}{DDS\+\_\+\+Status\+Condition}) and attaching them to a \doxylink{group__DDSConditionsModule_gaffdc85b9ca97eb432a2c17c52bc00f82}{DDS\+\_\+\+Wait\+Set}. \end{DoxyItemize}
\begin{DoxyItemize}
\item It then waits on that \doxylink{group__DDSConditionsModule_gaffdc85b9ca97eb432a2c17c52bc00f82}{DDS\+\_\+\+Wait\+Set} until the {\ttfamily trigger\+\_\+value} of one or several \doxylink{group__DDSConditionsModule_ga1c45ab3d5584bb3332e98266dc3f7d3d}{DDS\+\_\+\+Condition} objects become \doxylink{group__DDSCdrTypesModule_ga02f257a405ea7ff6774cdf4330a7eeb7}{DDS\+\_\+\+BOOLEAN\+\_\+\+TRUE}. \end{DoxyItemize}
\begin{DoxyItemize}
\item It then uses the result of the wait (i.\+e., {\ttfamily active\+\_\+conditions}, the list of \doxylink{group__DDSConditionsModule_ga1c45ab3d5584bb3332e98266dc3f7d3d}{DDS\+\_\+\+Condition} objects with {\ttfamily trigger\+\_\+value} == \doxylink{group__DDSCdrTypesModule_ga02f257a405ea7ff6774cdf4330a7eeb7}{DDS\+\_\+\+BOOLEAN\+\_\+\+TRUE}) to actually get the information\+: 
\begin{DoxyItemize}
\item by calling \doxylink{group__DDSEntityModule_ga805d3ec649b511a679b514b3ed044bfa}{DDS\+\_\+\+Entity\+\_\+get\+\_\+status\+\_\+changes} and then {\ttfamily get\+\_\+\texorpdfstring{$<$}{<}communication\+\_\+status\texorpdfstring{$>$}{>}}() on the relevant \doxylink{group__DDSEntityModule_ga928b59d917d674720975f0581149b905}{DDS\+\_\+\+Entity}, if the condition is a \doxylink{group__DDSConditionsModule_gab365a205f11e5da37e380ef825c74ecd}{DDS\+\_\+\+Status\+Condition} and the status changes, refer to plain communication status; 


\item by calling \doxylink{group__DDSEntityModule_ga805d3ec649b511a679b514b3ed044bfa}{DDS\+\_\+\+Entity\+\_\+get\+\_\+status\+\_\+changes} and then \doxylink{group__DDSReaderModule_ga84f8ad6ee21fb024234034bbcce6d812}{Foo\+Data\+Reader\+\_\+read()} or \doxylink{group__DDSReaderModule_gafa56233023b6c95f89a9df48d16a4659}{Foo\+Data\+Reader\+\_\+take} on the relevant \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader}, if the condition is a \doxylink{group__DDSConditionsModule_gab365a205f11e5da37e380ef825c74ecd}{DDS\+\_\+\+Status\+Condition} and the status changes refers to \doxylink{group__DDSStatusTypesModule_ggaa99b5585ecdf8c5f93ac3108439ad26fa9d2d926d515abd0ddd0b537efd42f03e}{DDS\+\_\+\+DATA\+\_\+\+AVAILABLE\+\_\+\+STATUS};  


\end{DoxyItemize}\end{DoxyItemize}
Usually the first step is done in an initialization phase, while the others are put in the application main loop. 

As there is no extra information passed from the middleware to the application when a wait returns (only the list of triggered \doxylink{group__DDSConditionsModule_ga1c45ab3d5584bb3332e98266dc3f7d3d}{DDS\+\_\+\+Condition} objects), \doxylink{group__DDSConditionsModule_ga1c45ab3d5584bb3332e98266dc3f7d3d}{DDS\+\_\+\+Condition} objects are meant to embed all that is needed to react properly when enabled. In particular, \doxylink{group__DDSEntityModule_ga928b59d917d674720975f0581149b905}{DDS\+\_\+\+Entity}-\/related conditions are related to exactly one \doxylink{group__DDSEntityModule_ga928b59d917d674720975f0581149b905}{DDS\+\_\+\+Entity} and cannot be shared. 

The result of a \doxylink{group__DDSConditionsModule_gaebdc837f4d5e7911c0b2de4f0c940bdc}{DDS\+\_\+\+Wait\+Set\+\_\+wait} operation depends on the state of the \doxylink{group__DDSConditionsModule_gaffdc85b9ca97eb432a2c17c52bc00f82}{DDS\+\_\+\+Wait\+Set}, which in turn depends on whether at least one attached \doxylink{group__DDSConditionsModule_ga1c45ab3d5584bb3332e98266dc3f7d3d}{DDS\+\_\+\+Condition} has a {\ttfamily trigger\+\_\+value} of \doxylink{group__DDSCdrTypesModule_ga02f257a405ea7ff6774cdf4330a7eeb7}{DDS\+\_\+\+BOOLEAN\+\_\+\+TRUE}. If the wait operation is called on \doxylink{group__DDSConditionsModule_gaffdc85b9ca97eb432a2c17c52bc00f82}{DDS\+\_\+\+Wait\+Set} with state BLOCKED, it will block the calling thread. If wait is called on a \doxylink{group__DDSConditionsModule_gaffdc85b9ca97eb432a2c17c52bc00f82}{DDS\+\_\+\+Wait\+Set} with state UNBLOCKED, it will return immediately. In addition, when the \doxylink{group__DDSConditionsModule_gaffdc85b9ca97eb432a2c17c52bc00f82}{DDS\+\_\+\+Wait\+Set} transitions from BLOCKED to UNBLOCKED it wakes up any threads that had called wait on it. 

A key aspect of the \doxylink{group__DDSConditionsModule_ga1c45ab3d5584bb3332e98266dc3f7d3d}{DDS\+\_\+\+Condition}/\doxylink{group__DDSConditionsModule_gaffdc85b9ca97eb432a2c17c52bc00f82}{DDS\+\_\+\+Wait\+Set} mechanism is the setting of the {\ttfamily trigger\+\_\+value} of each \doxylink{group__DDSConditionsModule_ga1c45ab3d5584bb3332e98266dc3f7d3d}{DDS\+\_\+\+Condition}. \hypertarget{group__DDSConditionsModule_WaitSet_trigger_status}{}\doxysubsubsubsubsection{\texorpdfstring{Trigger State of a \+::\+DDS\+\_\+\+Status\+Condition}{Trigger State of a \+::\+DDS\+\_\+\+Status\+Condition}}\label{group__DDSConditionsModule_WaitSet_trigger_status}
The {\ttfamily trigger\+\_\+value} of a \doxylink{group__DDSConditionsModule_gab365a205f11e5da37e380ef825c74ecd}{DDS\+\_\+\+Status\+Condition} is the boolean OR of the Changed\+Status\+Flag of all the communication statuses (see \doxylink{group__DDSStatusTypesModule}{Status Kinds}) to which it is sensitive. That is, {\ttfamily trigger\+\_\+value} == \doxylink{group__DDSCdrTypesModule_ga727fba6a96485884ccd9438b560689f7}{DDS\+\_\+\+BOOLEAN\+\_\+\+FALSE} only if all the values of the Changed\+Status\+Flags are \doxylink{group__DDSCdrTypesModule_ga727fba6a96485884ccd9438b560689f7}{DDS\+\_\+\+BOOLEAN\+\_\+\+FALSE}. 

The sensitivity of the \doxylink{group__DDSConditionsModule_gab365a205f11e5da37e380ef825c74ecd}{DDS\+\_\+\+Status\+Condition} to a particular communication status is controlled by the list of {\ttfamily enabled\+\_\+statuses} set on the condition by means of the \doxylink{group__DDSConditionsModule_gab2cb31f6955993ec9feaa3148e3ef2f9}{DDS\+\_\+\+Status\+Condition\+\_\+set\+\_\+enabled\+\_\+statuses} operation. \hypertarget{group__DDSConditionsModule_WaitSet_trigger_guard}{}\doxysubsubsubsubsection{\texorpdfstring{Trigger State of a \+::\+DDS\+\_\+\+Guard\+Condition}{Trigger State of a \+::\+DDS\+\_\+\+Guard\+Condition}}\label{group__DDSConditionsModule_WaitSet_trigger_guard}
The {\ttfamily trigger\+\_\+value} of a \doxylink{group__DDSConditionsModule_gaf554f2c5553ffb66e26cee169e409cb3}{DDS\+\_\+\+Guard\+Condition} is completely controlled by the application via the operation \doxylink{group__DDSConditionsModule_ga2c362db9e0b4fdc568aa655413b8ad8c}{DDS\+\_\+\+Guard\+Condition\+\_\+set\+\_\+trigger\+\_\+value}.
