\hypertarget{group__DDSDocGuideModule_doc_guide_naming_structs}{}\doxysubsubsubsection{\texorpdfstring{Structure \& Class Names}{Structure \& Class Names}}\label{group__DDSDocGuideModule_doc_guide_naming_structs}
RTI Connext DDS Micro makes a distinction between {\itshape value types} and {\itshape interface types}. Value types are types such as primitives, enumerations, strings, and structures whose identity and equality are determined solely by explicit state. Interface types are those abstract opaque data types that conceptually have an identity apart from their explicit state. Examples include all of the \doxylink{group__DDSEntityModule_ga928b59d917d674720975f0581149b905}{DDS\+\_\+\+Entity} subtypes. Instances of value types are frequently transitory and are declared on the stack. Instances of interface types typically have longer lifecycles, are accessible by pointer only, and may be managed by a factory object.

Value type structures are made more explicit through the use of C\textquotesingle{}s structure tag syntax. For example, a \doxylink{structDDS__Duration__t}{DDS\+\_\+\+Duration\+\_\+t} object must be declared as being of type "{}struct DDS\+\_\+\+Duration\+\_\+t,"{} not simply "{}\+DDS\+\_\+\+Duration\+\_\+t."{} Interface types, by contrast, are always of typedef\textquotesingle{}ed types; their underlying representations are opaque.\hypertarget{group__DDSDocGuideModule_doc_guide_doxygen}{}\doxysubsubsection{\texorpdfstring{API Documentation Terms}{API Documentation Terms}}\label{group__DDSDocGuideModule_doc_guide_doxygen}
In the API documentation, the term module refers to a logical grouping of documentation and elements in the API.
