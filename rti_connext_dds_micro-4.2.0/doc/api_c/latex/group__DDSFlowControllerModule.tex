\begin{DoxyParagraph}{QoS\+:}

Samples written by an asynchronous \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} are not sent in the context of the \doxylink{group__DDSWriterModule_ga2b106f9efd70a4da90b09a7216253aca}{Foo\+Data\+Writer\+\_\+write} call. Instead, the middleware puts the samples in a queue for future processing. The \doxylink{group__DDSFlowControllerModule_gac250f779038cbaa0e1bde24a4b33db05}{DDS\+\_\+\+Flow\+Controller} associated with each asynchronous Data\+Writer instance determines when the samples are actually sent. 

Each \doxylink{group__DDSFlowControllerModule_gac250f779038cbaa0e1bde24a4b33db05}{DDS\+\_\+\+Flow\+Controller} maintains a separate FIFO queue for each unique destination (remote application). Samples written by asynchronous \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} instances associated with the flow controller, are placed in the queues that correspond to the intended destinations of the sample. 

When tokens become available, a flow controller must decide which queue(s) to grant tokens first. This is determined by the flow controller\textquotesingle{}s scheduling policy. Once a queue has been granted tokens, it is serviced by the asynchronous publishing thread. The queued up samples will be coalesced and sent to the corresponding destination. The number of samples sent depends on the data size and the number of tokens granted. \begin{DoxyEnumFields}[2]{Enumerator}

Whenever tokens become available, the flow controller distributes the tokens uniformly across all of its (non-\/empty) destination queues. No destinations are prioritized. DDS\+\_\+\+EDF\+\_\+\+FLOW\+\_\+\+CONTROLLER\+\_\+\+SCHED\+\_\+\+POLICY&Indicates to flow control in an earliest-\/deadline-\/first fashion. A sample\textquotesingle{}s deadline is determined by the time it was written plus the latency budget of the Data\+Writer at the time of the write call (as specified in the \doxylink{structDDS__LatencyBudgetQosPolicy}{DDS\+\_\+\+Latency\+Budget\+Qos\+Policy}). The relative priority of a flow controller\textquotesingle{}s destination queue is determined by the earliest deadline across all samples it contains. 

When tokens become available, the \doxylink{group__DDSFlowControllerModule_gac250f779038cbaa0e1bde24a4b33db05}{DDS\+\_\+\+Flow\+Controller} distributes tokens to the destination queues in order of their deadline priority. In other words, the queue containing the sample with the earliest deadline is serviced first. The number of tokens granted equals the number of tokens required to send the first sample in the queue. Note that the priority of a queue may change as samples are sent (i.\+e. removed from the queue). If a sample must be sent to multiple destinations or two samples have an equal deadline value, the corresponding destination queues are serviced in a round-\/robin fashion. 

Hence, under the default \doxylink{structDDS__LatencyBudgetQosPolicy_a28d7a05d6a5559f3e174c5bebe0852b4}{DDS\+\_\+\+Latency\+Budget\+Qos\+Policy\+::duration} setting, an {\ttfamily EDF\+\_\+\+FLOW\+\_\+\+CONTROLLER\+\_\+\+SCHED\+\_\+\+POLICY} \doxylink{group__DDSFlowControllerModule_gac250f779038cbaa0e1bde24a4b33db05}{DDS\+\_\+\+Flow\+Controller} preserves the order in which the user calls \doxylink{group__DDSWriterModule_ga2b106f9efd70a4da90b09a7216253aca}{Foo\+Data\+Writer\+\_\+write} across the Data\+Writers associated with the flow controller. 

In other words, the priority of a destination queue is always determined by the earliest deadline among all samples contained in the queue. This priority inheritance approach is required in order to both honor the updated \doxylink{structDDS__LatencyBudgetQosPolicy_a28d7a05d6a5559f3e174c5bebe0852b4}{DDS\+\_\+\+Latency\+Budget\+Qos\+Policy\+::duration} and adhere to the \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} in-\/order data delivery guarantee.
