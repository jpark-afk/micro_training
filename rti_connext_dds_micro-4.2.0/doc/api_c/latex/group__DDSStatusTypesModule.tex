\doxysubsubsubsubsection{Detailed Description}
Kinds of communication status.

\doxylink{group__DDSEntityModule_ga928b59d917d674720975f0581149b905}{DDS\+\_\+\+Entity}

\doxylink{group__DDSQosTypesModule}{QoS Policies}

Each concrete \doxylink{group__DDSEntityModule_ga928b59d917d674720975f0581149b905}{DDS\+\_\+\+Entity} is associated with a set of Status objects whose value represents the communication status of that entity. Each status value can be accessed with a corresponding function on the \doxylink{group__DDSEntityModule_ga928b59d917d674720975f0581149b905}{DDS\+\_\+\+Entity}. 

RTI Connext DDS Micro supports a subset of these statuses. 

When these status values change, the proper \doxylink{structDDS__Listener}{DDS\+\_\+\+Listener} objects are invoked to asynchronously inform the application. 

An application is notified of communication status by means of the \doxylink{structDDS__Listener}{DDS\+\_\+\+Listener} mechanism. 

The statuses may be classified into\+: 

\begin{DoxyItemize}
\item {\itshape read communication statuses}\+: i.\+e., those that are related to arrival of data, namely \doxylink{group__DDSStatusTypesModule_ggaa99b5585ecdf8c5f93ac3108439ad26fa7962fc85687ca40e2674e4f66811f670}{DDS\+\_\+\+DATA\+\_\+\+ON\+\_\+\+READERS\+\_\+\+STATUS} and \doxylink{group__DDSStatusTypesModule_ggaa99b5585ecdf8c5f93ac3108439ad26fa9d2d926d515abd0ddd0b537efd42f03e}{DDS\+\_\+\+DATA\+\_\+\+AVAILABLE\+\_\+\+STATUS}. \end{DoxyItemize}
\begin{DoxyItemize}
\item {\itshape plain communication statuses}\+: i.\+e., all the others. \end{DoxyItemize}
Read communication statuses are treated slightly differently than the others because they don\textquotesingle{}t change independently. In other words, at least two changes will appear at the same time ( \doxylink{group__DDSStatusTypesModule_ggaa99b5585ecdf8c5f93ac3108439ad26fa7962fc85687ca40e2674e4f66811f670}{DDS\+\_\+\+DATA\+\_\+\+ON\+\_\+\+READERS\+\_\+\+STATUS} and \doxylink{group__DDSStatusTypesModule_ggaa99b5585ecdf8c5f93ac3108439ad26fa9d2d926d515abd0ddd0b537efd42f03e}{DDS\+\_\+\+DATA\+\_\+\+AVAILABLE\+\_\+\+STATUS}) and even several of the last kind may be part of the set. This \textquotesingle{}grouping\textquotesingle{} has to be communicated to the application. 

For each plain communication status, there is a corresponding structure to hold the status value. These values contain the information related to the change of status, as well as information related to the statuses themselves (e.\+g., contains cumulative counts). 

\hypertarget{group__DDSStatusTypesModule_Status_changes}{}\doxysubsubsubsubsection{\texorpdfstring{Changes in Status}{Changes in Status}}\label{group__DDSStatusTypesModule_Status_changes}
Associated with each one of an \doxylink{group__DDSEntityModule_ga928b59d917d674720975f0581149b905}{DDS\+\_\+\+Entity}\textquotesingle{}s communication status is a logical {\ttfamily Status\+Changed\+Flag}. This flag indicates whether that particular communication status has changed since the last time the status was read by the application. The way the status changes is slightly different for the Plain Communication Status and the Read Communication status. 

\hypertarget{dds_c_infrastructure.h_Status_changes_plain}{}\doxysubsubsubsubsubsection{\texorpdfstring{Changes in plain communication status}{Changes in plain communication status}}\label{dds_c_infrastructure.h_Status_changes_plain}
For the plain communication status, the {\ttfamily Status\+Changed\+Flag} flag is initially set to FALSE. It becomes TRUE whenever the plain communication status changes and it is reset to \doxylink{group__DDSCdrTypesModule_ga727fba6a96485884ccd9438b560689f7}{DDS\+\_\+\+BOOLEAN\+\_\+\+FALSE} each time the application accesses the plain communication status via the proper {\ttfamily get\+\_\+$<$plain communication status$>$()} operation on the \doxylink{group__DDSEntityModule_ga928b59d917d674720975f0581149b905}{DDS\+\_\+\+Entity}. 

The communication status is also reset to FALSE whenever the associated listener operation is called as the listener implicitly accesses the status which is passed as a parameter to the operation. The fact that the status is reset prior to calling the listener means that if the application calls the get\+\_\+$<$plain communication status$>$ from inside the listener it will see the status already reset. 

An exception to this rule is when the associated listener is the \textquotesingle{}nil\textquotesingle{} listener. The \textquotesingle{}nil\textquotesingle{} listener is treated as a NOOP and the act of calling the \textquotesingle{}nil\textquotesingle{} listener does not reset the communication status. 

\hypertarget{dds_c_infrastructure.h_Status_changes_read}{}\doxysubsubsubsubsubsection{\texorpdfstring{Changes in read communication status}{Changes in read communication status}}\label{dds_c_infrastructure.h_Status_changes_read}
For the read communication status, the {\ttfamily Status\+Changed\+Flag} flag is initially set to FALSE. The {\ttfamily Status\+Changed\+Flag} becomes TRUE when either a data-\/sample arrives or else the \doxylink{group__DDSViewStateModule_gab7a8a4ae44a2c00f411a4461135b45f1}{DDS\+\_\+\+View\+State\+Kind}, \doxylink{group__DDSSampleStateModule_gadb6d36e7c796da27519b6bf7f8f187e5}{DDS\+\_\+\+Sample\+State\+Kind}, or \doxylink{group__DDSInstanceStateModule_gaf2264cae1aa8cd66490debfdc5e0c360}{DDS\+\_\+\+Instance\+State\+Kind} of any existing sample changes for any reason other than a call to \doxylink{group__DDSReaderModule_gacf50e7b4ea6b82cf688bd96df1dd5ab4}{Foo\+Data\+Reader\+\_\+read\+\_\+next\+\_\+sample}, or \doxylink{group__DDSReaderModule_gac5f37ece5465c3e64077e8191c328d87}{Foo\+Data\+Reader\+\_\+take\+\_\+next\+\_\+sample}. Specifically any of the following events will cause the {\ttfamily Status\+Changed\+Flag} to become TRUE\+: 


\begin{DoxyItemize}
\item The arrival of new data. 


\item A change in the \doxylink{group__DDSInstanceStateModule_gaf2264cae1aa8cd66490debfdc5e0c360}{DDS\+\_\+\+Instance\+State\+Kind} of a contained instance. This can be caused by either\+: 


\begin{DoxyItemize}
\item The arrival of the notification that an instance has been disposed by\+: 
\begin{DoxyItemize}
\item the \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} that owns it if \doxylink{group__DDSOwnershipQosModule}{OWNERSHIP} QoS kind= \doxylink{group__DDSOwnershipQosModule_ggaa88100c64a26cc036cb2eb2d631c3f43a6f223289a81f87d7929408a84a27f316}{DDS\+\_\+\+EXCLUSIVE\+\_\+\+OWNERSHIP\+\_\+\+QOS} 
\item or by any \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} if \doxylink{group__DDSOwnershipQosModule}{OWNERSHIP} QoS kind= \doxylink{group__DDSOwnershipQosModule_ggaa88100c64a26cc036cb2eb2d631c3f43a262c9859d5c214495c02cd39366a335f}{DDS\+\_\+\+SHARED\+\_\+\+OWNERSHIP\+\_\+\+QOS} 
\end{DoxyItemize}
\item The loss of liveliness of the \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} of an instance for which there is no other \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer}.  
\item The arrival of the notification that an instance has been unregistered by the only \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} that is known to be writing the instance.  
\end{DoxyItemize}
\end{DoxyItemize}

Depending on the kind of {\ttfamily Status\+Changed\+Flag}, the flag transitions to FALSE again as follows\+: 
\begin{DoxyItemize}
\item The \doxylink{group__DDSStatusTypesModule_ggaa99b5585ecdf8c5f93ac3108439ad26fa9d2d926d515abd0ddd0b537efd42f03e}{DDS\+\_\+\+DATA\+\_\+\+AVAILABLE\+\_\+\+STATUS} {\ttfamily Status\+Changed\+Flag} becomes FALSE when either the corresponding listener operation (on\+\_\+data\+\_\+available) is called or the read\+\_\+next\+\_\+sample or take\+\_\+next\+\_\+sample operation is called on the associated \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader}.  
\item The \doxylink{group__DDSStatusTypesModule_ggaa99b5585ecdf8c5f93ac3108439ad26fa7962fc85687ca40e2674e4f66811f670}{DDS\+\_\+\+DATA\+\_\+\+ON\+\_\+\+READERS\+\_\+\+STATUS} {\ttfamily Status\+Changed\+Flag} becomes FALSE when any of the following events occurs\+: 
\begin{DoxyItemize}
\item The corresponding listener operation (on\+\_\+data\+\_\+on\+\_\+readers) is called.  
\item The on\+\_\+data\+\_\+available listener operation is called on any \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} belonging to the \doxylink{group__DDSSubscriberModule_ga2755712602505786a23baef5a42d6782}{DDS\+\_\+\+Subscriber}.  
\item The read or take operation (or their variants) is called on any \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} belonging to the \doxylink{group__DDSSubscriberModule_ga2755712602505786a23baef5a42d6782}{DDS\+\_\+\+Subscriber}.  
\end{DoxyItemize}
\end{DoxyItemize}

Type for {\itshape status} kinds. 

Each concrete \doxylink{group__DDSEntityModule_ga928b59d917d674720975f0581149b905}{DDS\+\_\+\+Entity} is associated with a set of {\ttfamily \texorpdfstring{$\ast$}{*}\+Status} objects whose values represent the communication status of that \doxylink{group__DDSEntityModule_ga928b59d917d674720975f0581149b905}{DDS\+\_\+\+Entity}.

The changes on these status values cause activation of the corresponding trigger invocation of the proper \doxylink{structDDS__Listener}{DDS\+\_\+\+Listener} objects to asynchronously inform the application.
