Modifies the value of a data instance. 

When this operation is used, RTI Connext DDS Micro will automatically supply the value of the {\ttfamily source\+\_\+timestamp} that is made available to \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} objects by means of the {\ttfamily source\+\_\+timestamp} attribute inside the \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info}. Gets a sample managed by the Data\+Writer. 

This operation is supported while using Zero Copy transfer or Flat\+Data language binding.  

\doxylink{group__DDSWriterModule_gad0273edf424235cff792ca704092315b}{Foo\+Data\+Writer\+\_\+get\+\_\+loan} fails with \doxylink{group__DDSReturnTypesModule_gga73f148aaf96b5f6f9fc630b7cfeb0c91a3a638871d5b4174c32c8d2880f1f6770}{DDS\+\_\+\+RETCODE\+\_\+\+PRECONDITION\+\_\+\+NOT\+\_\+\+MET} if the above conditions are not satisfied. 

The loaned sample is obtained from a Data\+Writer-\/managed sample pool and is uninitialized by default. An initialized sample can be obtained by setting \doxylink{structDDS__DataWriterResourceLimitsQosPolicy_a853628f860f77a13627f232fde71af80}{DDS\+\_\+\+Data\+Writer\+Resource\+Limits\+Qos\+Policy\+::initialize\+\_\+writer\+\_\+loaned\+\_\+sample} to \doxylink{group__DDSCdrTypesModule_ga02f257a405ea7ff6774cdf4330a7eeb7}{DDS\+\_\+\+BOOLEAN\+\_\+\+TRUE}. The \doxylink{structDDS__DataWriterResourceLimitsQosPolicy_a3573400a04c05813f29f72ed761665dc}{DDS\+\_\+\+Data\+Writer\+Resource\+Limits\+Qos\+Policy\+::writer\+\_\+loaned\+\_\+sample\+\_\+allocation} settings can be used to configure the Data\+Writer-\/managed sample pool. 

\doxylink{group__DDSWriterModule_gad0273edf424235cff792ca704092315b}{Foo\+Data\+Writer\+\_\+get\+\_\+loan} fails with \doxylink{group__DDSReturnTypesModule_gga73f148aaf96b5f6f9fc630b7cfeb0c91a35b4c98bf40ced0114572156c7f41893}{DDS\+\_\+\+RETCODE\+\_\+\+OUT\+\_\+\+OF\+\_\+\+RESOURCES} if \doxylink{structDDS__DataWriterResourceLimitsQosPolicy_a3573400a04c05813f29f72ed761665dc}{DDS\+\_\+\+Data\+Writer\+Resource\+Limits\+Qos\+Policy\+::writer\+\_\+loaned\+\_\+sample\+\_\+allocation} samples have been loaned, and none of those samples has been written with \doxylink{group__DDSWriterModule_ga2b106f9efd70a4da90b09a7216253aca}{Foo\+Data\+Writer\+\_\+write} or discarded via \doxylink{group__DDSWriterModule_ga37a6425b0d50db3cd8795604abe0593d}{Foo\+Data\+Writer\+\_\+discard\+\_\+loan}. 

Samples returned from \doxylink{group__DDSWriterModule_gad0273edf424235cff792ca704092315b}{Foo\+Data\+Writer\+\_\+get\+\_\+loan} have an associated state. Due to the optimized nature of the write operation while using Zero Copy transfer over shared memory or Flat\+Data language binding, this sample state is used to control when a sample is available for reuse after the write operation. The possible sample states are free, allocated, removed or serialized. A sample that has never been allocated is "{}free"{}. \doxylink{group__DDSWriterModule_gad0273edf424235cff792ca704092315b}{Foo\+Data\+Writer\+\_\+get\+\_\+loan} takes a "{}free"{} or "{}removed"{} sample and makes it "{}allocated"{}. When a sample is written, its state transitions from "{}allocated"{} to "{}serialized"{}, and the Data\+Writer takes responsibility for returning the sample back to its sample pool. The sample remains in the "{}serialized"{} state until it is removed from the Data\+Writer queue. 

Sample removal behavior differs slightly when using the Shared Memory transport or the Zero Copy v2 transport. When using the Shared Memory transport with a reliable Data\+Writer, the sample is removed from the Data\+Writer\textquotesingle{}s queue when the sample is acknowledged by all Data\+Readers. For a best-\/effort Data\+Writer, the sample is removed from the queue immediately after the write operation. After the sample is removed from the Data\+Writer queue, the sample is put back into the sample pool, and its state transitions from "{}serialized"{} to "{}removed"{}. At this time, a new call to \doxylink{group__DDSWriterModule_gad0273edf424235cff792ca704092315b}{Foo\+Data\+Writer\+\_\+get\+\_\+loan} may return the same sample. 

When using Zero Copy v2 transport, Best Effort and Reliable Data\+Writers behave similarly. The samples are kept in the serialized state until the sample HISTORY.\+depth is reached. At that point they are removed from the Data\+Writer\textquotesingle{}s queue and put back into the sample pool. Since Zero Copy v2 provides automatic sample synchronization if the sample is currently being read by a Data\+Reader with the \doxylink{group__DDSReaderModule_gafa56233023b6c95f89a9df48d16a4659}{Foo\+Data\+Reader\+\_\+take} or \doxylink{group__DDSReaderModule_ga84f8ad6ee21fb024234034bbcce6d812}{Foo\+Data\+Reader\+\_\+read} APIs, the sample will not be removed from the Data\+Writer queue until the Data\+Reader returns the loan. 

A loaned sample should not be reused to write a new value after the first write operation. Instead, a new sample from \doxylink{group__DDSWriterModule_gad0273edf424235cff792ca704092315b}{Foo\+Data\+Writer\+\_\+get\+\_\+loan} should be used to write the new value. 

A loaned sample that has not been written can be returned to the Data\+Writer\textquotesingle{}s sample pool by using \doxylink{group__DDSWriterModule_ga37a6425b0d50db3cd8795604abe0593d}{Foo\+Data\+Writer\+\_\+discard\+\_\+loan}. 

A Data\+Writer writing a type annotated with @transfer\+\_\+mode(\+SHMEM\+\_\+\+REF) or @language\+\_\+binding(\+FLAT\+\_\+\+DATA) cannot write unmanaged samples that have not been returned from \doxylink{group__DDSWriterModule_gad0273edf424235cff792ca704092315b}{Foo\+Data\+Writer\+\_\+get\+\_\+loan}.
