\doxysubsubsection{Detailed Description}
{\itshape \doxylink{group__DDSDocGuideModule_a_st_cert}{\texorpdfstring{$<$}{<}\texorpdfstring{$<$}{<}cert\texorpdfstring{$>$}{>}\texorpdfstring{$>$}{>}}}  Specifies the behavior of RTI Connext DDS Micro in the case where the value of a sample changes (one or more times) before it can be successfully communicated to one or more existing subscribers. 

This {\ttfamily Qos\+Policy} controls whether RTI Connext DDS Micro should deliver only the most recent value, attempt to deliver all intermediate values, or do something in between. 

On the publishing side this policy controls the samples that should be maintained by the \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} on behalf of existing \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} entities. 

On the subscribing side it controls the samples that should be maintained until the application "{}takes"{} them from RTI Connext DDS Micro. 

RTI Connext DDS Micro supports \doxylink{group__DDSHistoryQosModule_gga96c54dadb2beb87b23776e766e282185a993d3120b7bbb347ce11e0e6f68b29ff}{DDS\+\_\+\+KEEP\+\_\+\+LAST\+\_\+\+HISTORY\+\_\+\+QOS} kind.

\hypertarget{structDDS__HistoryQosPolicy_DDSHistoryQosModule_usage}{}\doxysubsubsection{\texorpdfstring{Usage}{Usage}}\label{structDDS__HistoryQosPolicy_DDSHistoryQosModule_usage}
This policy controls the behavior of RTI Connext DDS Micro when the value of an instance changes before it is finally communicated to some of its existing \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} entities. 

For kind set to \doxylink{group__DDSHistoryQosModule_gga96c54dadb2beb87b23776e766e282185a993d3120b7bbb347ce11e0e6f68b29ff}{DDS\+\_\+\+KEEP\+\_\+\+LAST\+\_\+\+HISTORY\+\_\+\+QOS}, RTI Connext DDS Micro will only attempt to keep the latest values of the instance and discard the older ones. In this case, the value of {\ttfamily depth} regulates the maximum number of values (up to and including the most current one) RTI Connext DDS Micro will maintain and deliver. The default (and most common setting) for depth is 1, indicating that only the most recent value should be delivered. \hypertarget{dds_c_infrastructure.h_DDSHistoryQosModule_consistency}{}\doxysubsubsection{\texorpdfstring{Consistency}{Consistency}}\label{dds_c_infrastructure.h_DDSHistoryQosModule_consistency}
The setting of \doxylink{group__DDSHistoryQosModule}{HISTORY} {\ttfamily depth} must be consistent with the \doxylink{group__DDSResourceLimitsQosModule}{RESOURCE\+\_\+\+LIMITS} {\ttfamily max\+\_\+samples\+\_\+per\+\_\+instance}. For these two QoS to be consistent, they must verify that {\itshape depth \texorpdfstring{$<$}{<}= max\+\_\+samples\+\_\+per\+\_\+instance}.
