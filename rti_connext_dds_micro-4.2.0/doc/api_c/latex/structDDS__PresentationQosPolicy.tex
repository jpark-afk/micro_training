\doxysubsubsection{Detailed Description}
Specifies how the samples representing changes to data instances are presented to a subscribing application. 

{\bfseries{NOTE\+: This QoS policy can only be set when using the static discovery API on the \doxylink{structDDS__SubscriptionBuiltinTopicData}{DDS\+\_\+\+Subscription\+Builtin\+Topic\+Data}.}} 

However, a \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} always announces \doxylink{group__DDSPresentationQosModule_gga123d979f855f637f32eb525b778175b2a6d21a371adc6e10a62c2739171f5c22f}{DDS\+\_\+\+TOPIC\+\_\+\+PRESENTATION\+\_\+\+QOS} via discovery, enabling a \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} to match with a \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} that requests either \doxylink{group__DDSPresentationQosModule_gga123d979f855f637f32eb525b778175b2ab7e8c01f13b9c46013094fdee7d6af36}{DDS\+\_\+\+INSTANCE\+\_\+\+PRESENTATION\+\_\+\+QOS} or \doxylink{group__DDSPresentationQosModule_gga123d979f855f637f32eb525b778175b2a6d21a371adc6e10a62c2739171f5c22f}{DDS\+\_\+\+TOPIC\+\_\+\+PRESENTATION\+\_\+\+QOS}, increasing interoperability. 

A Data\+Reader supports only \doxylink{group__DDSPresentationQosModule_gga123d979f855f637f32eb525b778175b2ab7e8c01f13b9c46013094fdee7d6af36}{DDS\+\_\+\+INSTANCE\+\_\+\+PRESENTATION\+\_\+\+QOS}. 

This QoS policy controls the extent to which changes to data instances can be made dependent on each other and also the kind of dependencies that can be propagated and maintained by RTI Connext DDS Micro. Specifically, this policy affects the application\textquotesingle{}s ability to\+: 

\begin{DoxyItemize}
\item specify and receive coherent changes to instances \item specify the relative order in which changes are presented \end{DoxyItemize}

\doxylink{group__DDSPublisherModule_ga3ecc0192bac0cba03781b70cec3099c9}{DDS\+\_\+\+Publisher}, \doxylink{group__DDSSubscriberModule_ga2755712602505786a23baef5a42d6782}{DDS\+\_\+\+Subscriber} 
\end{DoxyParagraph}
\begin{DoxyParagraph}{Status\+:}
\doxylink{group__DDSStatusTypesModule_ggaa99b5585ecdf8c5f93ac3108439ad26fa1eb2a68f0c66c314784737a7728922b8}{DDS\+\_\+\+OFFERED\+\_\+\+INCOMPATIBLE\+\_\+\+QOS\+\_\+\+STATUS}, \doxylink{group__DDSStatusTypesModule_ggaa99b5585ecdf8c5f93ac3108439ad26fa126ff1b38cdfc905353cb2dac57b6796}{DDS\+\_\+\+REQUESTED\+\_\+\+INCOMPATIBLE\+\_\+\+QOS\+\_\+\+STATUS} 
\end{DoxyParagraph}
A \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} will usually receive data in the order that it was sent by a \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer}, and the data is presented to the \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} as soon as the application receives the next expected value. However, sometimes you may want a set of data for the same \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} to be presented to the \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} only after {\itshape all} of the elements of the set have been received. Or you may want the data to be presented in a different order than that in which it was received. Specifically for keyed data, you may want the middleware to present the data in keyed -- or {\itshape instance} -- order, such that samples pertaining to the same instance are presented together. 

The Presentation QoS policy allows you to specify different {\itshape scopes} of presentation\+: within a \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer}, across instances of a single \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer}, and even across multiple Data\+Writers used by different writers of a publisher. It also controls whether or not a set of changes within the scope is delivered at the same time or can be delivered as soon as each element is received. 

\begin{DoxyItemize}
\item {\ttfamily coherent\+\_\+access} controls whether RTI Connext DDS Micro will preserve the groupings of changes made by a publishing application by means of the operations begin\+\_\+coherent\+\_\+changes() and end\+\_\+coherent\+\_\+changes(). These operations are not supported. \end{DoxyItemize}
\begin{DoxyItemize}
\item {\ttfamily ordered\+\_\+access} controls whether RTI Connext DDS Micro will preserve the order of changes. \end{DoxyItemize}
\begin{DoxyItemize}
\item {\ttfamily access\+\_\+scope} controls the granularity of the other settings. See below\+: \end{DoxyItemize}
If {\ttfamily coherent\+\_\+access} is set, then the {\ttfamily access\+\_\+scope} controls the maximum extent of coherent changes. The behavior is as follows\+: 

\begin{DoxyItemize}
\item If {\ttfamily access\+\_\+scope} is set to \doxylink{group__DDSPresentationQosModule_gga123d979f855f637f32eb525b778175b2ab7e8c01f13b9c46013094fdee7d6af36}{DDS\+\_\+\+INSTANCE\+\_\+\+PRESENTATION\+\_\+\+QOS} (the default), the use of begin\+\_\+coherent\+\_\+changes() and end\+\_\+coherent\+\_\+changes() has no effect on how the subscriber can access the data, because with the scope limited to each instance, changes to separate instances are considered independent and thus cannot be grouped into a coherent set. \end{DoxyItemize}
\begin{DoxyItemize}
\item If {\ttfamily access\+\_\+scope} is set to \doxylink{group__DDSPresentationQosModule_gga123d979f855f637f32eb525b778175b2a6d21a371adc6e10a62c2739171f5c22f}{DDS\+\_\+\+TOPIC\+\_\+\+PRESENTATION\+\_\+\+QOS}, then coherent changes (indicated by their enclosure within calls to begin\+\_\+coherent\+\_\+changes() and end\+\_\+coherent\+\_\+changes() will be made available as such to each remote \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} independently. That is, changes made to instances within each individual \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} will be available as coherent with respect to other changes to instances in that same \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer}, but will not be grouped with changes made to instances belonging to a different \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer}. \end{DoxyItemize}
\begin{DoxyItemize}
\item If access\+\_\+scope is set to \doxylink{group__DDSPresentationQosModule_gga123d979f855f637f32eb525b778175b2ae0591a04e045da1d86f25fa8bec39937}{DDS\+\_\+\+GROUP\+\_\+\+PRESENTATION\+\_\+\+QOS}, then coherent changes made to instances through a \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} attached to a common \doxylink{group__DDSPublisherModule_ga3ecc0192bac0cba03781b70cec3099c9}{DDS\+\_\+\+Publisher} are made available as a unit to remote subscribers. \end{DoxyItemize}
If {\ttfamily ordered\+\_\+access} is set, then the {\ttfamily access\+\_\+scope} controls the maximum extent for which order will be preserved by RTI Connext DDS Micro. 

\begin{DoxyItemize}
\item If {\ttfamily access\+\_\+scope} is set to \doxylink{group__DDSPresentationQosModule_gga123d979f855f637f32eb525b778175b2ab7e8c01f13b9c46013094fdee7d6af36}{DDS\+\_\+\+INSTANCE\+\_\+\+PRESENTATION\+\_\+\+QOS} (the lowest level), then changes to each instance are considered unordered relative to changes to any other instance. That means that changes (creations, deletions, modifications) made to two instances are not necessarily seen in the order they occur. This is the case even if it is the same application thread making the changes using the same \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer}. \end{DoxyItemize}
\begin{DoxyItemize}
\item If {\ttfamily access\+\_\+scope} is set to \doxylink{group__DDSPresentationQosModule_gga123d979f855f637f32eb525b778175b2a6d21a371adc6e10a62c2739171f5c22f}{DDS\+\_\+\+TOPIC\+\_\+\+PRESENTATION\+\_\+\+QOS}, changes (creations, deletions, modifications) made by a single \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} are made available to subscribers in the same order they occur. Changes made to instances though different \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} entities are not necessarily seen in the order they occur. This is the case, even if the changes are made by a single application thread using \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} objects attached to the same \doxylink{group__DDSPublisherModule_ga3ecc0192bac0cba03781b70cec3099c9}{DDS\+\_\+\+Publisher}. \end{DoxyItemize}
\begin{DoxyItemize}
\item Finally, if access\+\_\+scope is set to \doxylink{group__DDSPresentationQosModule_gga123d979f855f637f32eb525b778175b2ae0591a04e045da1d86f25fa8bec39937}{DDS\+\_\+\+GROUP\+\_\+\+PRESENTATION\+\_\+\+QOS}, changes made to instances via \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} entities attached to the same \doxylink{group__DDSPublisherModule_ga3ecc0192bac0cba03781b70cec3099c9}{DDS\+\_\+\+Publisher} object are made available to subscribers on the same order they occur. \end{DoxyItemize}
Note that this QoS policy controls the scope at which related changes are made available to the subscriber. This means the subscriber {\bfseries{can}} access the changes in a coherent manner and in the proper order; however, it does not necessarily imply that the \doxylink{group__DDSSubscriberModule_ga2755712602505786a23baef5a42d6782}{DDS\+\_\+\+Subscriber} {\bfseries{will}} indeed access the changes in the correct order. For that to occur, the application at the subscriber end must use the proper logic in reading the \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} objects. \hypertarget{structDDS__PresentationQosPolicy_DDSPresentationQosModule_compatibility}{}\doxysubsubsection{\texorpdfstring{Compatibility}{Compatibility}}\label{structDDS__PresentationQosPolicy_DDSPresentationQosModule_compatibility}
