\item In the case where the \doxylink{structDDS__HistoryQosPolicy_a3cb2743cd13a81614bcc4f314cd640ab}{DDS\+\_\+\+History\+Qos\+Policy\+::kind} is \doxylink{group__DDSHistoryQosModule_gga96c54dadb2beb87b23776e766e282185a993d3120b7bbb347ce11e0e6f68b29ff}{DDS\+\_\+\+KEEP\+\_\+\+LAST\+\_\+\+HISTORY\+\_\+\+QOS}, the call will return at most \doxylink{structDDS__HistoryQosPolicy_aef0fb3fd3579866be17d1a936f5e3729}{DDS\+\_\+\+History\+Qos\+Policy\+::depth} samples per instance. \end{DoxyItemize}
\begin{DoxyItemize}
\item The maximum number of samples returned is limited by \doxylink{structDDS__ResourceLimitsQosPolicy_a90db906a3958146c5e22557db648e7ff}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy\+::max\+\_\+samples}. \end{DoxyItemize}
\begin{DoxyItemize}
\item For multiple instances, the number of samples returned is additionally limited by the product (\doxylink{structDDS__ResourceLimitsQosPolicy_ae3d9339bebf4c7163cf6dff82882cbef}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy\+::max\+\_\+samples\+\_\+per\+\_\+instance} \texorpdfstring{$\ast$}{*} \doxylink{structDDS__ResourceLimitsQosPolicy_ab7339605f314f50c7cb658426ff64cdb}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy\+::max\+\_\+instances}) \end{DoxyItemize}
If the read or take succeeds and the number of samples returned has been limited (by means of a maximum limit, as listed above, or insufficient \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} resources), the call will complete successfully and provide those samples the reader is able to return. The user may need to make additional calls, or return outstanding loaned buffers in the case of insuffificient resources, in order to access remaining samples. 

Note that in the case where the \doxylink{classDDSTopic}{DDSTopic} associated with the \doxylink{classDDSDataReader}{DDSData\+Reader} is bound to a data-\/type that has no key definition, then there will be at most one instance in the \doxylink{classDDSDataReader}{DDSData\+Reader}. So the per-\/sample limits will apply. 

The act of {\itshape taking} a sample removes it from RTI Connext DDS Micro so it cannot be read or taken again. If the sample belongs to the most recent generation of the instance, it will also set the {\ttfamily view\+\_\+state} of the sample\textquotesingle{}s instance to \doxylink{group__DDSViewStateModule_ggab7a8a4ae44a2c00f411a4461135b45f1ad0a3502068e5e66e20a873a0aaa881be}{DDS\+\_\+\+NOT\+\_\+\+NEW\+\_\+\+VIEW\+\_\+\+STATE}. It will not affect the {\ttfamily instance\+\_\+state} of the sample\textquotesingle{}s instance. 

After \doxylink{classDDSDataReader_a924c8a8e10df47c5597ca01533e5a640}{DDSData\+Reader\+::take\+\_\+untyped} completes, {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+seq} will be of the same length and contain the received data. 

If the sequences are empty (maximum size equal 0) when the \doxylink{classDDSDataReader_a924c8a8e10df47c5597ca01533e5a640}{DDSData\+Reader\+::take\+\_\+untyped} is called, the samples returned in the {\ttfamily received\+\_\+data} and the corresponding {\ttfamily info\+\_\+seq} are \textquotesingle{}loaned\textquotesingle{} to the application from buffers provided by the \doxylink{classDDSDataReader}{DDSData\+Reader}. The application can use them as desired and has guaranteed exclusive access to them. 

Once the application completes its use of the samples it must \textquotesingle{}return the loan\textquotesingle{} to the \doxylink{classDDSDataReader}{DDSData\+Reader} by calling the \doxylink{classDDSDataReader_a7532ba67aded9911329c34fe3e3af1cd}{DDSData\+Reader\+::return\+\_\+loan\+\_\+untyped} operation. 

{\itshape Note\+:} While you must call \doxylink{classDDSDataReader_a7532ba67aded9911329c34fe3e3af1cd}{DDSData\+Reader\+::return\+\_\+loan\+\_\+untyped} at some point, you do {\itshape not} have to do so before the next \doxylink{classDDSDataReader_a924c8a8e10df47c5597ca01533e5a640}{DDSData\+Reader\+::take\+\_\+untyped} call. However, failure to return the loan will eventually deplete the \doxylink{classDDSDataReader}{DDSData\+Reader} of the buffers it needs to receive new samples and eventually samples will start to be lost. The total number of buffers available to the \doxylink{classDDSDataReader}{DDSData\+Reader} is specified by the \doxylink{structDDS__ResourceLimitsQosPolicy}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy} and the \doxylink{structDDS__DataReaderResourceLimitsQosPolicy}{DDS\+\_\+\+Data\+Reader\+Resource\+Limits\+Qos\+Policy}. 

If the sequences are not empty (maximum size not equal 0) when the \doxylink{classDDSDataReader_a924c8a8e10df47c5597ca01533e5a640}{DDSData\+Reader\+::take\+\_\+untyped} is called, samples are copied to received\+\_\+data and info\+\_\+seq. The application will not need to call \doxylink{structFooDataReader_ad9ef915c38563e3a06e1ec8f8287730a}{Foo\+Data\+Reader\+::return\+\_\+loan}. 

If the \doxylink{classDDSDataReader}{DDSData\+Reader} has no samples that meet the constraints, the method will fail with \doxylink{group__DDSReturnTypesModule_gga73f148aaf96b5f6f9fc630b7cfeb0c91aa8e69444ae8a8efa65bde05556818669}{DDS\+\_\+\+RETCODE\+\_\+\+NO\+\_\+\+DATA}. 

In addition to the collection of samples, the read and take operations also use a collection of \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} structures. \hypertarget{classDDSDataReader_Data_and_sampleinfo_sequence_take_untyped}{}\doxysubsubsection{\texorpdfstring{SEQUENCES USAGE IN TAKE AND READ}{SEQUENCES USAGE IN TAKE AND READ}}\label{classDDSDataReader_Data_and_sampleinfo_sequence_take_untyped}
The initial (input) properties of the {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+seq} collections will determine the precise behavior of the read or take operation. For the purposes of this description, the collections are modeled as having these properties\+:  \begin{DoxyItemize}
\item whether the collection container owns the memory of the elements within ({\ttfamily owns}, see \+::\+Foo\+Seq\+::has\+\_\+ownership)  \item the current-\/length ({\ttfamily len}, see \+::\+Foo\+Seq\+::length()) \item the maximum length ({\ttfamily max\+\_\+len}, see \+::\+Foo\+Seq\+::maximum()) \end{DoxyItemize}
The initial values of the  {\ttfamily owns},  {\ttfamily len} and {\ttfamily max\+\_\+len} properties for the {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+seq} collections govern the behavior of the read and take operations as specified by the following rules\+: 


\begin{DoxyEnumerate}
\item The values of  {\ttfamily owns},  {\ttfamily len} and {\ttfamily max\+\_\+len} properties for the two collections must be identical. Otherwise read/take will fail with \doxylink{group__DDSReturnTypesModule_gga73f148aaf96b5f6f9fc630b7cfeb0c91a3a638871d5b4174c32c8d2880f1f6770}{DDS\+\_\+\+RETCODE\+\_\+\+PRECONDITION\+\_\+\+NOT\+\_\+\+MET}. 


\item On successful output, the values of  {\ttfamily owns},  {\ttfamily len} and {\ttfamily max\+\_\+len} will be the same for both collections. 


\item If the initial {\ttfamily max\+\_\+len==0}, then the {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+seq} collections will be filled with elements that are loaned by the \doxylink{classDDSDataReader}{DDSData\+Reader}. On output,  {\ttfamily owns} will be FALSE,  {\ttfamily len} will be set to the number of values returned, and {\ttfamily max\+\_\+len} will be set to a value verifying {\ttfamily max\+\_\+len} \texorpdfstring{$>$}{>}= {\ttfamily len}. The use of this variant allows for zero-\/copy access to the data and the application will need to return the loan to the \doxylink{classDDSDataWriter}{DDSData\+Writer} using \doxylink{structFooDataReader_ad9ef915c38563e3a06e1ec8f8287730a}{Foo\+Data\+Reader\+::return\+\_\+loan}. 


\item If the initial {\ttfamily max\+\_\+len\texorpdfstring{$>$}{>}0}  and {\ttfamily owns==FALSE},  then the read or take operation will fail with \doxylink{group__DDSReturnTypesModule_gga73f148aaf96b5f6f9fc630b7cfeb0c91a3a638871d5b4174c32c8d2880f1f6770}{DDS\+\_\+\+RETCODE\+\_\+\+PRECONDITION\+\_\+\+NOT\+\_\+\+MET}. This avoids the potential hard-\/to-\/detect memory leaks caused by an application forgetting to return the loan. 


\item If initial {\ttfamily max\+\_\+len\texorpdfstring{$>$}{>}0}  and {\ttfamily owns==TRUE},  then the read or take operation will copy the {\ttfamily received\+\_\+data} values and \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} values into the elements already inside the collections. On output,  {\ttfamily owns} will be TRUE,  {\ttfamily len} will be set to the number of values copied and {\ttfamily max\+\_\+len} will remain unchanged. The use of this variant forces a copy but the application can control where the copy is placed and the application will not need to return the loan. The number of samples copied depends on the relative values of {\ttfamily max\+\_\+len} and {\ttfamily max\+\_\+samples\+:} 


\begin{DoxyItemize}
\item If {\ttfamily max\+\_\+samples} == LENGTH\+\_\+\+UNLIMITED, then at most {\ttfamily max\+\_\+len} values will be copied. The use of this variant lets the application limit the number of samples returned to what the sequence can accommodate. 


\item If {\ttfamily max\+\_\+samples} \texorpdfstring{$<$}{<}= {\ttfamily max\+\_\+len}, then at most {\ttfamily max\+\_\+samples} values will be copied. The use of this variant lets the application limit the number of samples returned to fewer that what the sequence can accommodate.  


\item If {\ttfamily max\+\_\+samples} \texorpdfstring{$>$}{>} {\ttfamily max\+\_\+len}, then the read or take operation will fail with \doxylink{group__DDSReturnTypesModule_gga73f148aaf96b5f6f9fc630b7cfeb0c91a3a638871d5b4174c32c8d2880f1f6770}{DDS\+\_\+\+RETCODE\+\_\+\+PRECONDITION\+\_\+\+NOT\+\_\+\+MET}. This avoids the potential confusion where the application expects to be able to access up to {\ttfamily max\+\_\+samples}, but that number can never be returned, even if they are available in the \doxylink{classDDSDataReader}{DDSData\+Reader}, because the output sequence cannot accommodate them. 
\end{DoxyItemize}
\end{DoxyEnumerate}

As described above, upon completion, the {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+seq} collections may contain elements loaned from the \doxylink{classDDSDataReader}{DDSData\+Reader}. If this is the case, the application will need to use \doxylink{classDDSDataReader_a7532ba67aded9911329c34fe3e3af1cd}{DDSData\+Reader\+::return\+\_\+loan\+\_\+untyped} to return the loan once it is no longer using the {\ttfamily received\+\_\+data} in the collection. When \doxylink{classDDSDataReader_a7532ba67aded9911329c34fe3e3af1cd}{DDSData\+Reader\+::return\+\_\+loan\+\_\+untyped} completes, the collection will have  {\ttfamily owns=FALSE} and  {\ttfamily max\+\_\+len=0}. The application can determine whether it is necessary to return the loan or not based on how the state of the collections when the read/take operation was called  or by accessing the {\ttfamily owns} property.  However, in many cases it may be simpler to always call \doxylink{classDDSDataReader_a7532ba67aded9911329c34fe3e3af1cd}{DDSData\+Reader\+::return\+\_\+loan\+\_\+untyped}, as this operation is harmless (i.\+e., it leaves all elements unchanged) if the collection does not have a loan. 

To avoid potential memory leaks, the implementation of the Foo and \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} collections should disallow changing the length of a collection for which {\ttfamily owns==FALSE}. Furthermore, deleting a collection for which {\ttfamily owns==FALSE} should be considered an error.  

On output, the collection of Foo values and the collection of \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} structures are of the same length and are in a one-\/to-\/one correspondence. Each \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} provides information, such as the source\+\_\+timestamp, the sample\+\_\+state, view\+\_\+state, and instance\+\_\+state, etc., about the corresponding sample. 

Some elements in the returned collection may not have valid data. If the instance\+\_\+state in the \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} is \doxylink{group__DDSInstanceStateModule_ggaf2264cae1aa8cd66490debfdc5e0c360a51e7b0651e135e656327002e41787dbf}{DDS\+\_\+\+NOT\+\_\+\+ALIVE\+\_\+\+DISPOSED\+\_\+\+INSTANCE\+\_\+\+STATE} or \doxylink{group__DDSInstanceStateModule_ggaf2264cae1aa8cd66490debfdc5e0c360a72ebdc6f53c9a7588458b48e3ea66507}{DDS\+\_\+\+NOT\+\_\+\+ALIVE\+\_\+\+NO\+\_\+\+WRITERS\+\_\+\+INSTANCE\+\_\+\+STATE}, then the last sample for that instance in the collection (that is, the one whose \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} has sample\+\_\+rank==0) does not contain valid data. 

Samples that contain no data do not count towards the limits imposed by the \doxylink{structDDS__ResourceLimitsQosPolicy}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy}. The act of reading/taking a sample sets its sample\+\_\+state to \doxylink{group__DDSSampleStateModule_ggadb6d36e7c796da27519b6bf7f8f187e5a4435d5fd0a36806ebd1c67210345a70b}{DDS\+\_\+\+READ\+\_\+\+SAMPLE\+\_\+\+STATE}. 

If the sample belongs to the most recent generation of the instance, it will also set the view\+\_\+state of the instance to \doxylink{group__DDSViewStateModule_ggab7a8a4ae44a2c00f411a4461135b45f1ad0a3502068e5e66e20a873a0aaa881be}{DDS\+\_\+\+NOT\+\_\+\+NEW\+\_\+\+VIEW\+\_\+\+STATE}. It will not affect the instance\+\_\+state of the instance. 

This operation must be provided on the specialized class that is generated for the particular application data-\/type that is being read . It is not necessary for an application to return the loans immediately after the read or take calls. However, as these buffers correspond to internal resources inside the \doxylink{classDDSDataReader}{DDSData\+Reader}, the application should not retain them indefinitely.
