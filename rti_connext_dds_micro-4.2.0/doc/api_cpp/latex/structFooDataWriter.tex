When this operation is used, RTI Connext DDS Micro will automatically supply the value of the {\ttfamily source\+\_\+timestamp} that is made available to \doxylink{classDDSDataReader}{DDSData\+Reader} objects by means of the {\ttfamily source\+\_\+timestamp} attribute inside the \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info}. As a side effect, this operation asserts liveliness on the \doxylink{classDDSDataWriter}{DDSData\+Writer} itself, the \doxylink{classDDSPublisher}{DDSPublisher} and the \doxylink{classDDSDomainParticipant}{DDSDomain\+Participant}. 

Note that the special value \doxylink{group__DDSUserDataModule_ga7974338d80c6817f16f77899d908a60e}{DDS\+\_\+\+HANDLE\+\_\+\+NIL} can be used for the parameter {\ttfamily handle}. This indicates the identity of the instance should be automatically deduced from the {\ttfamily instance\+\_\+data} (by means of the {\ttfamily key}). 

If {\ttfamily handle} is any value other than \doxylink{group__DDSUserDataModule_ga7974338d80c6817f16f77899d908a60e}{DDS\+\_\+\+HANDLE\+\_\+\+NIL}, then it must correspond to an instance that has been registered. If there is no correspondence, the operation will fail with \doxylink{group__DDSReturnTypesModule_gga73f148aaf96b5f6f9fc630b7cfeb0c91ad8661c51c31806806aaf10dca3c80f6c}{DDS\+\_\+\+RETCODE\+\_\+\+BAD\+\_\+\+PARAMETER}. 

RTI Connext DDS Micro will not detect the error when the {\ttfamily handle} is any value other than \doxylink{group__DDSUserDataModule_ga7974338d80c6817f16f77899d908a60e}{DDS\+\_\+\+HANDLE\+\_\+\+NIL}, corresponds to an instance that has been registered, but does not correspond to the instance deduced from the {\ttfamily instance\+\_\+data} (by means of the {\ttfamily key}). RTI Connext DDS Micro will treat as if the \doxylink{structFooDataWriter_ab2c44dd15f5daf7eddf3773239101478}{write()} operation is for the instance as indicated by the {\ttfamily handle}. 

This operation may block if the \doxylink{group__DDSReliabilityQosModule}{RELIABILITY} {\ttfamily kind} is set to \doxylink{group__DDSReliabilityQosModule_ggaf09e82d431c2328186c7fb4b3fa9ad91ae5d04022c6405f9db6406489956d1923}{DDS\+\_\+\+RELIABLE\+\_\+\+RELIABILITY\+\_\+\+QOS} and the modification would cause data to be lost or else cause one of the limits specified in the \doxylink{group__DDSResourceLimitsQosModule}{RESOURCE\+\_\+\+LIMITS} to be exceeded.

Informs RTI Connext DDS Micro that the application will be modifying a particular instance. 

This operation is only useful for keyed data types. Using it for non-\/keyed types causes no effect and returns \doxylink{group__DDSUserDataModule_ga7974338d80c6817f16f77899d908a60e}{DDS\+\_\+\+HANDLE\+\_\+\+NIL}. The operation takes as a parameter an instance (of which only the key value is examined) and returns a {\ttfamily handle} that can be used in successive \doxylink{structFooDataWriter_ab2c44dd15f5daf7eddf3773239101478}{write()} or \doxylink{structFooDataWriter_a82698123a576af876c614ea3d2ce5cc5}{dispose()} operations. 

The operation gives RTI Connext DDS Micro an opportunity to pre-\/configure itself to improve performance. 

The use of this operation by an application is optional even for keyed types. If an instance has not been pre-\/registered, the application can use the special value \doxylink{group__DDSUserDataModule_ga7974338d80c6817f16f77899d908a60e}{DDS\+\_\+\+HANDLE\+\_\+\+NIL} as the \doxylink{group__DDSUserDataModule_ga2cd7a0bbf330870ab93f94e05c92318b}{DDS\+\_\+\+Instance\+Handle\+\_\+t} paramater to the write or dispose operation and RTI Connext DDS Micro will auto-\/register the instance. 

For best performance, the operation should be invoked prior to calling any operation that modifies the instance, such as \doxylink{structFooDataWriter_ab2c44dd15f5daf7eddf3773239101478}{Foo\+Data\+Writer\+::write}, \doxylink{structFooDataWriter_a2d8af76eb0a89175785d696879566bbb}{Foo\+Data\+Writer\+::write\+\_\+w\+\_\+timestamp}, \doxylink{structFooDataWriter_a82698123a576af876c614ea3d2ce5cc5}{Foo\+Data\+Writer\+::dispose} and \doxylink{structFooDataWriter_a50906cab978f822bca3a65ea52bc9801}{Foo\+Data\+Writer\+::dispose\+\_\+w\+\_\+timestamp} and the handle used in conjunction with the data for those calls. 

When this operation is used, RTI Connext DDS Micro will automatically supply the value of the {\ttfamily source\+\_\+timestamp} that is used. 

This operation may fail and return \doxylink{group__DDSUserDataModule_ga7974338d80c6817f16f77899d908a60e}{DDS\+\_\+\+HANDLE\+\_\+\+NIL} if \doxylink{structDDS__ResourceLimitsQosPolicy_ab7339605f314f50c7cb658426ff64cdb}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy\+::max\+\_\+instances} limit has been exceeded. 

The operation is {\bfseries{idempotent}}. If it is called for an already registered instance, it just returns the already allocated handle. This may be used to lookup and retrieve the handle allocated to a given instance. 

This operation can only be called after \doxylink{classDDSDataWriter}{DDSData\+Writer} has been enabled. Otherwise, \doxylink{group__DDSUserDataModule_ga7974338d80c6817f16f77899d908a60e}{DDS\+\_\+\+HANDLE\+\_\+\+NIL} will be returned.

The loaned sample is obtained from a Data\+Writer-\/managed sample pool and is uninitialized by default. An initialized sample can be obtained by setting \doxylink{structDDS__DataWriterResourceLimitsQosPolicy_a853628f860f77a13627f232fde71af80}{DDS\+\_\+\+Data\+Writer\+Resource\+Limits\+Qos\+Policy\+::initialize\+\_\+writer\+\_\+loaned\+\_\+sample} to \doxylink{group__DDSCdrTypesModule_ga02f257a405ea7ff6774cdf4330a7eeb7}{DDS\+\_\+\+BOOLEAN\+\_\+\+TRUE}. Samples returned from \doxylink{structFooDataWriter_ab7a9f5031701c3495235fb85f591007c}{Foo\+Data\+Writer\+::get\+\_\+loan} have an associated state. Due to the optimized nature of the write operation while using Zero Copy transfer over shared memory or Flat\+Data language binding, this sample state is used to control when a sample is available for reuse after the write operation. The possible sample states are free, allocated, removed or serialized. A sample that has never been allocated is "{}free"{}. \doxylink{structFooDataWriter_ab7a9f5031701c3495235fb85f591007c}{Foo\+Data\+Writer\+::get\+\_\+loan} takes a "{}free"{} or "{}removed"{} sample and makes it "{}allocated"{}. When a sample is written, its state transitions from "{}allocated"{} to "{}serialized"{}, and the Data\+Writer takes responsibility for returning the sample back to its sample pool. The sample remains in the "{}serialized"{} state until it is removed from the Data\+Writer queue. 

Sample removal behavior differs slightly when using the Shared Memory transport or the Zero Copy v2 transport. When using the Shared Memory transport with a reliable Data\+Writer, the sample is removed from the Data\+Writer\textquotesingle{}s queue when the sample is acknowledged by all Data\+Readers. For a best-\/effort Data\+Writer, the sample is removed from the queue immediately after the write operation. After the sample is removed from the Data\+Writer queue, the sample is put back into the sample pool, and its state transitions from "{}serialized"{} to "{}removed"{}. At this time, a new call to \doxylink{structFooDataWriter_ab7a9f5031701c3495235fb85f591007c}{Foo\+Data\+Writer\+::get\+\_\+loan} may return the same sample. 

When using Zero Copy v2 transport, Best Effort and Reliable Data\+Writers behave similarly. The samples are kept in the serialized state until the sample HISTORY.\+depth is reached. At that point they are removed from the Data\+Writer\textquotesingle{}s queue and put back into the sample pool. Since Zero Copy v2 provides automatic sample synchronization if the sample is currently being read by a Data\+Reader with the \doxylink{structFooDataReader_a683dd6f8d92d8eb73ea32e42dc7ffe99}{Foo\+Data\+Reader\+::take} or \doxylink{structFooDataReader_a609495a4932f84f968291878df6fea01}{Foo\+Data\+Reader\+::read} APIs, the sample will not be removed from the Data\+Writer queue until the Data\+Reader returns the loan. 

A loaned sample should not be reused to write a new value after the first write operation. Instead, a new sample from \doxylink{structFooDataWriter_ab7a9f5031701c3495235fb85f591007c}{Foo\+Data\+Writer\+::get\+\_\+loan} should be used to write the new value. 

A loaned sample that has not been written can be returned to the Data\+Writer\textquotesingle{}s sample pool by using \doxylink{structFooDataWriter_acfa8f678188a9f59796e9a5003959eb6}{Foo\+Data\+Writer\+::discard\+\_\+loan}. 

A Data\+Writer writing a type annotated with @transfer\+\_\+mode(\+SHMEM\+\_\+\+REF) or @language\+\_\+binding(\+FLAT\+\_\+\+DATA) cannot write unmanaged samples that have not been returned from \doxylink{structFooDataWriter_ab7a9f5031701c3495235fb85f591007c}{Foo\+Data\+Writer\+::get\+\_\+loan}.
