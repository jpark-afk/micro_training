NETIO Zero Copy v2 interface.

◆ NDDS_Transport_ZeroCopy_initialize()

NETIO_ZCOPYDllExport RTI_BOOL NDDS_Transport_ZeroCopy_initialize ( RT_Registry_T * registry,
const char * transport_name,
struct ZCOPY_NotifInterfaceFactoryProperty * property )

Initialize RTI Connext DDS Micro with Zero Copy support. It is required to initialize the library before using the Zero Copy transport.

Initializing the library updates the registry by registering the factories required for the Zero Copy transport. To use the transport, a Notification Transport must also be registered. This registration is optional during initialization and may be performed either at initialization time or later.

This function initializes RTI Connext DDS Micro with Zero Copy support. It always initializes the Zero Copy library, and it conditionally registers a Zero Copy transport depending on the arguments provided. If a transport name is specified, it is used; otherwise the default transport name is applied. If properties are provided, the Zero Copy transport is registered and configured using those properties.

Parameters
[in]registryThe registry to register the transport with.
[in]transport_nameThe name of the transport. If NULL, the default transport name will be used.
[in]propertyA pointer to the properties for the Zero Copy notification interface. If NULL, the transport will not be registered.
Returns
RTI_TRUE if the initialization was successful, RTI_FALSE otherwise.
Note
It is acceptable for transport_name and property to be NULL. If transport_name is NULL, the default transport name is used. If property is NULL, the transport is not registered.
When Zero Copy v2 is enabled as a transport in DDS_TransportQosPolicy::enabled_transports, it requires one additional timer; refer to OSAPI_SystemProperty::max_timers for details.
