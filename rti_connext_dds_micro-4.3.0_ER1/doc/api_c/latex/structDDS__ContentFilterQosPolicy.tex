\hypertarget{structDDS__ContentFilterQosPolicy_DDSContentFilterQosModule_usage}{}\doxysubsubsection{\texorpdfstring{Usage}{Usage}}\label{structDDS__ContentFilterQosPolicy_DDSContentFilterQosModule_usage}
The CONTENT\+\_\+\+FILTER QoS policy allows a \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} to specify that it is interested only in (potentially) a subset of the samples on its topic. Once a content filter is configured, the \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} will only receive samples that pass the filter. If content filtering is supported by the \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer}, samples that do not pass the filter may not be sent at all, thus reducing the network bandwidth usage. 

A \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} will fail to be created if it specifies a \doxylink{structDDS__ContentFilterQosPolicy}{DDS\+\_\+\+Content\+Filter\+Qos\+Policy} and the content filtering feature is not enabled for its parent \doxylink{group__DDSDomainParticipantModule_ga1964274885335d5bcea6855f66b0bfe1}{DDS\+\_\+\+Domain\+Participant}. It will also fail to be created if the \doxylink{structDDS__ContentFilterQosPolicy}{DDS\+\_\+\+Content\+Filter\+Qos\+Policy} specifies a filter that is not compatible with the resource limits specified in the \doxylink{structDDS__FilterQosPolicy}{DDS\+\_\+\+Filter\+Qos\+Policy} for its parent \doxylink{group__DDSDomainParticipantModule_ga1964274885335d5bcea6855f66b0bfe1}{DDS\+\_\+\+Domain\+Participant}. 

Generally, RTI Connext DDS Micro does not support changing the QoS of DDS entities after they are enabled. \doxylink{structDDS__ContentFilterQosPolicy}{DDS\+\_\+\+Content\+Filter\+Qos\+Policy} is an exception to this rule, since it can be updated at runtime using \doxylink{group__DDSReaderModule_gac6edf6c1cb03f06c3647ee838b279de8}{DDS\+\_\+\+Data\+Reader\+\_\+set\+\_\+qos}. 

For all strings contained in this QoS, be sure to follow the \doxysectlink{group__DDSStringClass_DDSStringClass_conventions}{Conventions}{1} for allocating and freeing memory. In particular, if you use \doxylink{group__DDSReaderModule_ga09dfd320506e72b6236c939caba93887}{DDS\+\_\+\+Data\+Reader\+Qos\+\_\+finalize} to finalize the \doxylink{structDDS__DataReaderQos}{DDS\+\_\+\+Data\+Reader\+Qos}, it will expect that all strings in the \doxylink{structDDS__ContentFilterQosPolicy}{DDS\+\_\+\+Content\+Filter\+Qos\+Policy} are owned by the policy and will attempt to free them when finalizing the QoS. Therefore, it is recommended to use \doxylink{group__DDSStringClass_gaab34d3575bf66cd95a890f7e21eb697a}{DDS\+\_\+\+String\+\_\+dup} to duplicate all strings that you want to use in the \doxylink{structDDS__ContentFilterQosPolicy}{DDS\+\_\+\+Content\+Filter\+Qos\+Policy}.
