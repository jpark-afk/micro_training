\doxysubsubsection{Detailed Description}
RTPS well-\/known port mapping configuration. 

RTI Connext DDS Micro uses the RTPS wire protocol. The discovery protocols defined by RTPS rely on well-\/known ports to initiate discovery. These well-\/known ports define the multicast and unicast ports on which a Participant will listen for discovery {\bfseries{metatraffic}} from other Participants. The discovery metatraffic contains all the information required to establish the presence of remote DDS entities in the network. 

The well-\/known ports are defined by RTPS in terms of port mapping expressions with several tunable parameters, which allow the user to customize what network ports are used by the middleware. These parameters are exposed in \doxylink{structDDS__RtpsWellKnownPorts__t}{DDS\+\_\+\+Rtps\+Well\+Known\+Ports\+\_\+t}. In order for all Participants in a system to correctly discover each other, it is important that they all use the same port mapping expressions. 

The actual port mapping expressions, as defined by the RTPS specification, can be found below. In addition to the parameters listed in \doxylink{structDDS__RtpsWellKnownPorts__t}{DDS\+\_\+\+Rtps\+Well\+Known\+Ports\+\_\+t}, the port numbers depend on\+: 

-\/ {\ttfamily domain\+\_\+id}, as specified in \doxylink{group__DDSDomainParticipantFactoryModule_ga5901b073073fffe523a806a79262649c}{DDS\+\_\+\+Domain\+Participant\+Factory\+\_\+create\+\_\+participant} 

-\/ {\ttfamily participant\+\_\+id}, as specified using \doxylink{structDDS__WireProtocolQosPolicy_af8282d78bd332c9b82d0112fab8c63d7}{DDS\+\_\+\+Wire\+Protocol\+Qos\+Policy\+::participant\+\_\+id} 

The {\ttfamily domain\+\_\+id} parameter ensures no port conflicts exist between Participants belonging to different domains. This also means that discovery metatraffic in one domain is not visible to Participants in a different domain. The {\ttfamily participant\+\_\+id} parameter ensures that unique unicast port numbers are assigned to Participants belonging to the same domain on a given host. 

The {\itshape metatraffic\+\_\+unicast\+\_\+port} is used to exchange discovery metatraffic using unicast. \begin{DoxyVerb}metatraffic_unicast_port = port_base + (domain_id_gain * domain_id) + (participant_id_gain * participant_id) + builtin_unicast_port_offset  \end{DoxyVerb}
 

The {\itshape metatraffic\+\_\+multicast\+\_\+port} is used to exchange discovery metatraffic using multicast. \begin{DoxyVerb}metatraffic_multicast_port = port_base + (domain_id_gain * domain_id) + builtin_multicast_port_offset  \end{DoxyVerb}
 

RTPS also defines the {\itshape default} multicast and unicast ports on which \doxylink{group__DDSReaderModule_ga49ce0cab2c1b60ddee4784a1432577a4}{DDS\+\_\+\+Data\+Reader} and \doxylink{group__DDSWriterModule_gafb74fa54675abe1bfb2090265bf4d116}{DDS\+\_\+\+Data\+Writer} entities receive {\bfseries{user}} traffic. 

The {\itshape usertraffic\+\_\+unicast\+\_\+port} is used to exchange user data using unicast. \begin{DoxyVerb}usertraffic_unicast_port = port_base + (domain_id_gain * domain_id) + (participant_id_gain * participant_id) + user_unicast_port_offset  \end{DoxyVerb}
 

The {\itshape usertraffic\+\_\+multicast\+\_\+port} is used to exchange user data using multicast. The corresponding multicast group addresses can be configured using \begin{DoxyVerb}usertraffic_multicast_port = port_base + (domain_id_gain * domain_id) + user_multicast_port_offset  \end{DoxyVerb}
 

By default, the port mapping parameters are configured to be compliant with OMG\textquotesingle{}s DDS Interoperability Wire Protocol (see also \doxylink{group__DDSWireProtocolQosModule_ga8e1c02e92ccc930c8b89cafeeaf95045}{DDS\+\_\+\+INTEROPERABLE\+\_\+\+RTPS\+\_\+\+WELL\+\_\+\+KNOWN\+\_\+\+PORTS}). 

The OMG\textquotesingle{}s DDS Interoperability Wire Protocol compliant port mapping parameters are {\itshape not} backwards compatible with previous versions of the RTI Connext DDS Micro middleware. 

When modifying the port mapping parameters, care must be taken to avoid port aliasing. This would result in undefined discovery behavior. The chosen parameter values will also determine the maximum possible number of domains in the system and the maximum number of participants per domain. Additionally, any resulting mapped port number must be within the range imposed by the underlying transport. For example, for UDPv4, this range typically equals \mbox{[}1024 -\/ 65535\mbox{]}.
