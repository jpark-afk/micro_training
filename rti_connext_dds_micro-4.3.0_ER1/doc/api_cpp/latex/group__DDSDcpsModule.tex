\hypertarget{group__DDSDcpsModule_DDSDcps_overview}{}\doxysubsubsection{\texorpdfstring{Overview}{Overview}}\label{group__DDSDcpsModule_DDSDcps_overview}


Information flows with the aid of the following constructs\+: \doxylink{classDDSPublisher}{DDSPublisher} and \doxylink{classDDSDataWriter}{DDSData\+Writer} on the sending side, \doxylink{classDDSSubscriber}{DDSSubscriber} and \doxylink{classDDSDataReader}{DDSData\+Reader} on the receiving side.


\begin{DoxyItemize}
\item A \doxylink{classDDSPublisher}{DDSPublisher} is an object responsible for data distribution. It may publish data of different data types. A \doxylink{classDDSDataWriter}{DDSData\+Writer} acts as an accessor to a publisher -\/ each \doxylink{classDDSDataWriter}{DDSData\+Writer} object is dedicated to one application data type. A \doxylink{classDDSDataWriter}{DDSData\+Writer} is the object the application must use to communicate to a publisher the existence and value of data-\/objects of a given type. When data-\/object values have been communicated to the publisher through the appropriate data-\/writer, it is the publisher\textquotesingle{}s responsibility to perform the distribution (the publisher will do this according to its own QoS, or the QoS attached to the corresponding data-\/writer). A {\itshape publication} is defined by the association of a data-\/writer to a publisher. This association expresses the intent of the application to publish the data described by the data-\/writer in the context provided by the publisher.
\item A \doxylink{classDDSSubscriber}{DDSSubscriber} is an object responsible for receiving published data and making it available (according to the Subscriber\textquotesingle{}s QoS) to the receiving application. It may receive and dispatch data of different specified types. To access the received data, the application must use a \doxylink{classDDSDataReader}{DDSData\+Reader} attached to the subscriber. Thus, a {\itshape subscription} is defined by the association of a data-\/reader with a subscriber. This association expresses the intent of the application to subscribe to the data described by the data-\/reader in the context provided by the subscriber.
\end{DoxyItemize}

\doxylink{classDDSTopic}{DDSTopic} objects conceptually fit between publications and subscriptions. Publications must be known in such a way that subscriptions can refer to them unambiguously. A \doxylink{classDDSTopic}{DDSTopic} is meant to fulfill that purpose\+: it associates a name (unique in the domain i.\+e. the set of applications that are communicating with each other), a data type, and QoS related to the data itself. In addition to the topic QoS, the QoS of the \doxylink{classDDSDataWriter}{DDSData\+Writer} associated with that Topic and the QoS of the \doxylink{classDDSPublisher}{DDSPublisher} associated to the \doxylink{classDDSDataWriter}{DDSData\+Writer} control the behavior on the publisher\textquotesingle{}s side, while the corresponding \doxylink{classDDSTopic}{DDSTopic}, \doxylink{classDDSDataReader}{DDSData\+Reader} and \doxylink{classDDSSubscriber}{DDSSubscriber} QoS control the behavior on the subscriber\textquotesingle{}s side.

When an application wishes to publish data of a given type, it must create a \doxylink{classDDSPublisher}{DDSPublisher} (or reuse an already created one) and a \doxylink{classDDSDataWriter}{DDSData\+Writer} with all the characteristics of the desired publication. Similarly, when an application wishes to receive data, it must create a \doxylink{classDDSSubscriber}{DDSSubscriber} (or reuse an already created one) and a \doxylink{classDDSDataReader}{DDSData\+Reader} to define the subscription.\hypertarget{group__DDSDcpsModule_DDSDcps_model}{}\doxysubsubsection{\texorpdfstring{Conceptual Model}{Conceptual Model}}\label{group__DDSDcpsModule_DDSDcps_model}
The overall conceptual model is shown below.



Notice that all the main communication objects (the specializations of Entity) follow unified patterns of\+:


\begin{DoxyItemize}
\item Supporting QoS (made up of several Qos\+Policy); QoS provides a generic mechanism for the application to control the behavior of the Service and tailor it to its needs. Each \doxylink{classDDSEntity}{DDSEntity} supports its own specialized kind of QoS policies (see \doxylink{group__DDSQosTypesModule}{QoS Policies}).
\item Accepting a \doxylink{classDDSListener}{DDSListener}; listeners provide a generic mechanism for the middleware to notify the application of relevant asynchronous events, such as arrival of data corresponding to a subscription, violation of a QoS setting, etc. Each \doxylink{classDDSEntity}{DDSEntity} supports its own specialized kind of listener. Listeners are related to changes in status conditions (see \doxylink{group__DDSStatusTypesModule}{Status Kinds}). ~\newline
 ~\newline
 Note that only one Listener per entity is allowed (instead of a list of them). The reason for that choice is that this allows a much simpler (and, thus, more efficient) implementation as far as the middleware is concerned. Moreover, if it were required, the application could easily implement a listener that, when triggered, triggers in return attached \textquotesingle{}sub-\/listeners\textquotesingle{}.
\end{DoxyItemize}

All DCPS entities are attached to a \doxylink{classDDSDomainParticipant}{DDSDomain\+Participant}. A domain participant represents the local membership of the application in a domain. A {\itshape domain} is a distributed concept that links all the applications able to communicate with each other. It represents a communication plane\+: only the publishers and the subscribers attached to the same domain may interact.

\doxylink{classDDSDomainEntity}{DDSDomain\+Entity} is an intermediate object whose only purpose is to state that a Domain\+Participant cannot contain other domain participants.

At the DCPS level, data types represent information that is sent atomically. For performance reasons, only plain data structures are handled by this level.

By definition, a \doxylink{classDDSTopic}{DDSTopic} corresponds to a single data type. However, several topics may refer to the same data type. Therefore, a \doxylink{classDDSTopic}{DDSTopic} identifies data of a single type, ranging from one single instance to a whole collection of instances of that given type. This is shown below for the hypothetical data type {\ttfamily Foo}.



In case a set of instances is gathered under the same topic, different instances must be distinguishable. This is achieved by means of the values of some data fields that form the {\bfseries{key}} to that data set. The {\itshape key description} (i.\+e., the list of data fields whose value forms the key) has to be indicated to the middleware. The rule is simple\+: {\itshape different data samples with the same key value represent successive values for the same instance, while different data samples with different key values represent different instances}. If no key is provided, the data set associated with the \doxylink{classDDSTopic}{DDSTopic} is restricted to a {\itshape single instance}.

Topics need to be known by the middleware and potentially propagated. Topic objects are created using the create operations provided by \doxylink{classDDSDomainParticipant}{DDSDomain\+Participant}.

The interaction style is straightforward on the publisher\textquotesingle{}s side\+: when the application decides that it wants to make data available for publication, it calls the appropriate operation on the related \doxylink{classDDSDataWriter}{DDSData\+Writer} (this, in turn, will trigger its \doxylink{classDDSPublisher}{DDSPublisher}).

On the subscriber\textquotesingle{}s side however, there are more choices\+: relevant information may arrive when the application is busy doing something else or when the application is just waiting for that information. Therefore, depending on the way the application is designed, asynchronous notifications or synchronous access may be more appropriate. Both interaction modes are allowed, a \doxylink{classDDSListener}{DDSListener} is used to provide a callback for asynchronous access, and polling allows for synchronous access.\hypertarget{group__DDSDcpsModule_DDSDcps_packages}{}\doxysubsubsection{\texorpdfstring{Modules}{Modules}}\label{group__DDSDcpsModule_DDSDcps_packages}
