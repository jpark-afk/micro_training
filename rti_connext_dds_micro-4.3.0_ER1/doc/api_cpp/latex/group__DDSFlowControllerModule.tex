Samples written by an asynchronous \doxylink{classDDSDataWriter}{DDSData\+Writer} are not sent in the context of the \doxylink{structFooDataWriter_ab2c44dd15f5daf7eddf3773239101478}{Foo\+Data\+Writer\+::write} call. Instead, the middleware puts the samples in a queue for future processing. The \doxylink{classDDSFlowController}{DDSFlow\+Controller} associated with each asynchronous Data\+Writer instance determines when the samples are actually sent. 

Each \doxylink{classDDSFlowController}{DDSFlow\+Controller} maintains a separate FIFO queue for each unique destination (remote application). Samples written by asynchronous \doxylink{classDDSDataWriter}{DDSData\+Writer} instances associated with the flow controller, are placed in the queues that correspond to the intended destinations of the sample. 

When tokens become available, a flow controller must decide which queue(s) to grant tokens first. This is determined by the flow controller\textquotesingle{}s scheduling policy. Once a queue has been granted tokens, it is serviced by the asynchronous publishing thread. The queued up samples will be coalesced and sent to the corresponding destination. A sample\textquotesingle{}s deadline is determined by the time it was written plus the latency budget of the Data\+Writer at the time of the write call (as specified in the \doxylink{structDDS__LatencyBudgetQosPolicy}{DDS\+\_\+\+Latency\+Budget\+Qos\+Policy}). The relative priority of a flow controller\textquotesingle{}s destination queue is determined by the earliest deadline across all samples it contains. 

When tokens become available, the \doxylink{classDDSFlowController}{DDSFlow\+Controller} distributes tokens to the destination queues in order of their deadline priority. In other words, the queue containing the sample with the earliest deadline is serviced first. The number of tokens granted equals the number of tokens required to send the first sample in the queue. Note that the priority of a queue may change as samples are sent (i.\+e. removed from the queue). If a sample must be sent to multiple destinations or two samples have an equal deadline value, the corresponding destination queues are serviced in a round-\/robin fashion. 

Hence, under the default \doxylink{structDDS__LatencyBudgetQosPolicy_a28d7a05d6a5559f3e174c5bebe0852b4}{DDS\+\_\+\+Latency\+Budget\+Qos\+Policy\+::duration} setting, an {\ttfamily EDF\+\_\+\+FLOW\+\_\+\+CONTROLLER\+\_\+\+SCHED\+\_\+\+POLICY} \doxylink{classDDSFlowController}{DDSFlow\+Controller} preserves the order in which the user calls \doxylink{structFooDataWriter_ab2c44dd15f5daf7eddf3773239101478}{Foo\+Data\+Writer\+::write} across the Data\+Writers associated with the flow controller. 

In other words, the priority of a destination queue is always determined by the earliest deadline among all samples contained in the queue. This priority inheritance approach is required in order to both honor the updated \doxylink{structDDS__LatencyBudgetQosPolicy_a28d7a05d6a5559f3e174c5bebe0852b4}{DDS\+\_\+\+Latency\+Budget\+Qos\+Policy\+::duration} and adhere to the \doxylink{classDDSDataWriter}{DDSData\+Writer} in-\/order data delivery guarantee.
