Indicates to the \doxylink{classDDSDataReader}{DDSData\+Reader} that the application is done accessing the collection of {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+seq} obtained by some earlier invocation of read or take on the \doxylink{classDDSDataReader}{DDSData\+Reader}. 

This operation indicates to the \doxylink{classDDSDataReader}{DDSData\+Reader} that the application is done accessing the collection of {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+seq} obtained by some earlier invocation of read or take on the \doxylink{classDDSDataReader}{DDSData\+Reader}. 

The {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+seq} must belong to a single related "{}pair"{}; that is, they should correspond to a pair returned from a single call to read or take. The {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+seq} must also have been obtained from the same \doxylink{classDDSDataReader}{DDSData\+Reader} to which they are returned. If either of these conditions is not met, the operation will fail with \doxylink{group__DDSReturnTypesModule_gga73f148aaf96b5f6f9fc630b7cfeb0c91a3a638871d5b4174c32c8d2880f1f6770}{DDS\+\_\+\+RETCODE\+\_\+\+PRECONDITION\+\_\+\+NOT\+\_\+\+MET}. 

The operation \doxylink{structFooDataReader_ad9ef915c38563e3a06e1ec8f8287730a}{Foo\+Data\+Reader\+::return\+\_\+loan} allows implementations of the read and take operations to "{}loan"{} buffers from the \doxylink{classDDSDataReader}{DDSData\+Reader} to the application and in this manner provide "{}zerocopy"{} access to the data. During the loan, the \doxylink{classDDSDataReader}{DDSData\+Reader} will guarantee that the data and sample-\/information are not modified. 

It is not necessary for an application to return the loans immediately after the read or take calls. However, as these buffers correspond to internal resources inside the \doxylink{classDDSDataReader}{DDSData\+Reader}, the application should not retain them indefinitely. 

The use of \doxylink{structFooDataReader_ad9ef915c38563e3a06e1ec8f8287730a}{Foo\+Data\+Reader\+::return\+\_\+loan} is only necessary if the read or take calls "{}loaned"{} buffers to the application. This only occurs if the {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+\+Seq} collections had {\ttfamily max\+\_\+len=0} at the time read or take was called. 

The application may also examine the "{}owns"{} property of the collection to determine where there is an outstanding loan. However, calling \doxylink{structFooDataReader_ad9ef915c38563e3a06e1ec8f8287730a}{Foo\+Data\+Reader\+::return\+\_\+loan} on a collection that does not have a loan is safe and has no side effects.  

If the collections had a loan, upon completion of \doxylink{structFooDataReader_ad9ef915c38563e3a06e1ec8f8287730a}{Foo\+Data\+Reader\+::return\+\_\+loan}, the collections will have {\ttfamily max\+\_\+len=0}. 

Similar to read, this operation must be provided on the specialized class that is generated for the particular application data-\/type that is being taken.

Access a collection of data samples from the \doxylink{classDDSDataReader}{DDSData\+Reader}. 

This operation offers the same functionality and API as \doxylink{structFooDataReader_a683dd6f8d92d8eb73ea32e42dc7ffe99}{Foo\+Data\+Reader\+::take} except that the samples returned remain in the \doxylink{classDDSDataReader}{DDSData\+Reader} such that they can be retrieved again by means of a read or take operation. 

Please refer to the documentation of \doxylink{structFooDataReader_a683dd6f8d92d8eb73ea32e42dc7ffe99}{Foo\+Data\+Reader\+::take()} for details on the number of samples returned within the received\+\_\+data and info\+\_\+seq as well as the order in which the samples appear in these sequences. 

The act of reading a sample changes its {\ttfamily sample\+\_\+state} to \doxylink{group__DDSSampleStateModule_ggadb6d36e7c796da27519b6bf7f8f187e5a4435d5fd0a36806ebd1c67210345a70b}{DDS\+\_\+\+READ\+\_\+\+SAMPLE\+\_\+\+STATE}. If the sample belongs to the most recent generation of the instance, it will also set the {\ttfamily view\+\_\+state} of the instance to be \doxylink{group__DDSViewStateModule_ggab7a8a4ae44a2c00f411a4461135b45f1ad0a3502068e5e66e20a873a0aaa881be}{DDS\+\_\+\+NOT\+\_\+\+NEW\+\_\+\+VIEW\+\_\+\+STATE}. It will not affect the {\ttfamily instance\+\_\+state} of the instance. 

{\itshape Important\+:} If the samples "{}returned"{} by this method are loaned from RTI Connext DDS Micro (see \doxylink{structFooDataReader_a683dd6f8d92d8eb73ea32e42dc7ffe99}{Foo\+Data\+Reader\+::take} for more information on memory loaning), it is important that their contents not be changed. Because the memory in which the data is stored belongs to the middleware, any modifications made to the data will be seen the next time the same samples are read or taken; the samples will no longer reflect the state that was received from the network.

\mbox{\hyperlink{group__DDSReturnTypesModule_ga73f148aaf96b5f6f9fc630b7cfeb0c91}{DDS\+\_\+\+Return\+Code\+\_\+t}} Foo\+Data\+Reader\+::take (\begin{DoxyParamCaption}\item[{\mbox{\hyperlink{structFooSeq}{Foo\+Seq}} \&}]{received\+\_\+data}{, }\item[{\mbox{\hyperlink{structDDS__SampleInfoSeq}{DDS\+\_\+\+Sample\+Info\+Seq}} \&}]{info\+\_\+seq}{, }\item[{\mbox{\hyperlink{group__DDSCdrTypesModule_gafdb4033c1f3f81cfe8c9592532461b17}{DDS\+\_\+\+Long}}}]{max\+\_\+samples}{, }\item[{\mbox{\hyperlink{group__DDSSampleStateModule_ga00cf17a2dec95fc16ffd02c57ef356f5}{DDS\+\_\+\+Sample\+State\+Mask}}}]{sample\+\_\+states}{, }\item[{\mbox{\hyperlink{group__DDSViewStateModule_gac6c18247f611af71486839446604e18c}{DDS\+\_\+\+View\+State\+Mask}}}]{view\+\_\+states}{, }\item[{\mbox{\hyperlink{group__DDSInstanceStateModule_ga4ded4022b3281636f4fbee19aab2844f}{DDS\+\_\+\+Instance\+State\+Mask}}}]{instance\+\_\+states}{}\end{DoxyParamCaption})}



Access a collection of data-\/samples from the \doxylink{classDDSDataReader}{DDSData\+Reader}. 

The operation will return the list of samples received by the \doxylink{classDDSDataReader}{DDSData\+Reader} since the last \doxylink{structFooDataReader_a683dd6f8d92d8eb73ea32e42dc7ffe99}{Foo\+Data\+Reader\+::take} operation that match the specified \doxylink{group__DDSSampleStateModule_ga00cf17a2dec95fc16ffd02c57ef356f5}{DDS\+\_\+\+Sample\+State\+Mask}, \doxylink{group__DDSViewStateModule_gac6c18247f611af71486839446604e18c}{DDS\+\_\+\+View\+State\+Mask}, and \doxylink{group__DDSInstanceStateModule_ga4ded4022b3281636f4fbee19aab2844f}{DDS\+\_\+\+Instance\+State\+Mask}. 

This operation may fail with \doxylink{group__DDSReturnTypesModule_gga73f148aaf96b5f6f9fc630b7cfeb0c91ac47a8e813f6e5d652f67dbc551b9f62e}{DDS\+\_\+\+RETCODE\+\_\+\+ERROR} if the \doxylink{structDDS__DataReaderResourceLimitsQosPolicy_a82873fd35e4159bce6c23cc0de5fcca9}{DDS\+\_\+\+Data\+Reader\+Resource\+Limits\+Qos\+Policy\+::max\+\_\+outstanding\+\_\+reads} limit has been exceeded. 

The actual number of samples returned depends on the information that has been received by the middleware as well as the \doxylink{structDDS__HistoryQosPolicy}{DDS\+\_\+\+History\+Qos\+Policy}, \doxylink{structDDS__ResourceLimitsQosPolicy}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy}, \doxylink{structDDS__DataReaderResourceLimitsQosPolicy}{DDS\+\_\+\+Data\+Reader\+Resource\+Limits\+Qos\+Policy}, and the characteristics of the data-\/type that is associated with the \doxylink{classDDSDataReader}{DDSData\+Reader}\+: 

\begin{DoxyItemize}
\item When the \doxylink{structDDS__HistoryQosPolicy_a3cb2743cd13a81614bcc4f314cd640ab}{DDS\+\_\+\+History\+Qos\+Policy\+::kind} is \doxylink{group__DDSHistoryQosModule_gga96c54dadb2beb87b23776e766e282185a993d3120b7bbb347ce11e0e6f68b29ff}{DDS\+\_\+\+KEEP\+\_\+\+LAST\+\_\+\+HISTORY\+\_\+\+QOS}, the call will return a maximum of \doxylink{structDDS__HistoryQosPolicy_aef0fb3fd3579866be17d1a936f5e3729}{DDS\+\_\+\+History\+Qos\+Policy\+::depth} samples for each ALIVE instance and \doxylink{structDDS__HistoryQosPolicy_aef0fb3fd3579866be17d1a936f5e3729}{DDS\+\_\+\+History\+Qos\+Policy\+::depth} + 1 samples for each NOT\+\_\+\+ALIVE instance. The extra sample is an invalid sample that indicates the instance state transition from ALIVE to NOT\+\_\+\+ALIVE. \end{DoxyItemize}
\begin{DoxyItemize}
\item When the \doxylink{structDDS__HistoryQosPolicy_a3cb2743cd13a81614bcc4f314cd640ab}{DDS\+\_\+\+History\+Qos\+Policy\+::kind} is \doxylink{group__DDSHistoryQosModule_gga96c54dadb2beb87b23776e766e282185a9e526d876dae232aa083125c72135f5b}{DDS\+\_\+\+KEEP\+\_\+\+ALL\+\_\+\+HISTORY\+\_\+\+QOS}, the maximum number of samples returned is limited to \doxylink{structDDS__ResourceLimitsQosPolicy_a90db906a3958146c5e22557db648e7ff}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy\+::max\+\_\+samples} + 1 for each NOT\+\_\+\+ALIVE instance. \end{DoxyItemize}
\begin{DoxyItemize}
\item When max\+\_\+samples\+\_\+per\+\_\+instance is not DDS\+\_\+\+LENGTH\+\_\+\+UNLIMITED, the number of samples returned is also limited by the product (\doxylink{structDDS__ResourceLimitsQosPolicy_ae3d9339bebf4c7163cf6dff82882cbef}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy\+::max\+\_\+samples\+\_\+per\+\_\+instance} \texorpdfstring{$\ast$}{*} \doxylink{structDDS__ResourceLimitsQosPolicy_ab7339605f314f50c7cb658426ff64cdb}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy\+::max\+\_\+instances} ). \end{DoxyItemize}
If the read or take succeeds, and the number of samples returned has been limited (by means of a maximum limit, as listed above, or insufficient \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} resources), the call will complete successfully and provide those samples the reader is able to return. The user may need to make additional calls, or return outstanding loaned buffers in the case of insufficient resources, in order to access remaining samples. 

Note that in the case where the \doxylink{classDDSTopic}{DDSTopic} associated with the \doxylink{classDDSDataReader}{DDSData\+Reader} is bound to a data-\/type that has no key definition, then there will be at most one instance in the \doxylink{classDDSDataReader}{DDSData\+Reader}. So the per-\/sample limits will apply. 

The act of {\itshape taking} a sample removes it from RTI Connext DDS Micro so it cannot be read or taken again. If the sample belongs to the most recent generation of the instance, it will also set the {\ttfamily view\+\_\+state} of the sample\textquotesingle{}s instance to \doxylink{group__DDSViewStateModule_ggab7a8a4ae44a2c00f411a4461135b45f1ad0a3502068e5e66e20a873a0aaa881be}{DDS\+\_\+\+NOT\+\_\+\+NEW\+\_\+\+VIEW\+\_\+\+STATE}. It will not affect the {\ttfamily instance\+\_\+state} of the sample\textquotesingle{}s instance. 

After \doxylink{structFooDataReader_a683dd6f8d92d8eb73ea32e42dc7ffe99}{Foo\+Data\+Reader\+::take} completes, {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+seq} will be of the same length and contain the received data. 

If the sequences are empty (maximum size equal 0) when the \doxylink{structFooDataReader_a683dd6f8d92d8eb73ea32e42dc7ffe99}{Foo\+Data\+Reader\+::take} is called, the samples returned in the {\ttfamily received\+\_\+data} and the corresponding {\ttfamily info\+\_\+seq} are \textquotesingle{}loaned\textquotesingle{} to the application from buffers provided by the \doxylink{classDDSDataReader}{DDSData\+Reader}. The application can use them as desired and has guaranteed exclusive access to them. 

Once the application completes its use of the samples it must \textquotesingle{}return the loan\textquotesingle{} to the \doxylink{classDDSDataReader}{DDSData\+Reader} by calling the \doxylink{structFooDataReader_ad9ef915c38563e3a06e1ec8f8287730a}{Foo\+Data\+Reader\+::return\+\_\+loan} operation. 

{\itshape Note\+:} While you must call \doxylink{structFooDataReader_ad9ef915c38563e3a06e1ec8f8287730a}{Foo\+Data\+Reader\+::return\+\_\+loan} at some point, you do {\itshape not} have to do so before the next \doxylink{structFooDataReader_a683dd6f8d92d8eb73ea32e42dc7ffe99}{Foo\+Data\+Reader\+::take} call. However, failure to return the loan will eventually deplete the \doxylink{classDDSDataReader}{DDSData\+Reader} of the buffers it needs to receive new samples and eventually samples will start to be lost. The total number of buffers available to the \doxylink{classDDSDataReader}{DDSData\+Reader} is specified by the \doxylink{structDDS__ResourceLimitsQosPolicy}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy}. 

If the sequences are not empty (maximum size not equal 0) when the \doxylink{structFooDataReader_a683dd6f8d92d8eb73ea32e42dc7ffe99}{Foo\+Data\+Reader\+::take} is called, samples are copied to received\+\_\+data and info\+\_\+seq. The application will not need to call \doxylink{structFooDataReader_ad9ef915c38563e3a06e1ec8f8287730a}{Foo\+Data\+Reader\+::return\+\_\+loan}. 

The samples returned to the caller is a list where samples belonging to the same data instance are consecutive (i.\+e. instance access scope). 

Samples belonging to the same instance will appear in the relative order in which there were received (i.\+e. reception timestamp destination order, where earlier samples are ahead of later samples). 

If the \doxylink{classDDSDataReader}{DDSData\+Reader} has no samples that meet the constraints, the method will fail with \doxylink{group__DDSReturnTypesModule_gga73f148aaf96b5f6f9fc630b7cfeb0c91aa8e69444ae8a8efa65bde05556818669}{DDS\+\_\+\+RETCODE\+\_\+\+NO\+\_\+\+DATA}. 

In addition to the collection of samples, the read and take operations also use a collection of \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} structures. \hypertarget{structFooDataReader_Data_and_sampleinfo_sequence}{}\doxysubsubsection{\texorpdfstring{SEQUENCES USAGE IN TAKE AND READ}{SEQUENCES USAGE IN TAKE AND READ}}\label{structFooDataReader_Data_and_sampleinfo_sequence}
The initial (input) properties of the {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+seq} collections will determine the precise behavior of the read or take operation. For the purposes of this description, the collections are modeled as having these properties\+:  \begin{DoxyItemize}
\item whether the collection container owns the memory of the elements within ({\ttfamily owns}, see \+::\+Foo\+Seq\+::has\+\_\+ownership)  \item the current-\/length ({\ttfamily len}, see \+::\+Foo\+Seq\+::length()) \item the maximum length ({\ttfamily max\+\_\+len}, see \+::\+Foo\+Seq\+::maximum()) \end{DoxyItemize}
The initial values of the  {\ttfamily owns},  {\ttfamily len} and {\ttfamily max\+\_\+len} properties for the {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+seq} collections govern the behavior of the read and take operations as specified by the following rules\+: 


\begin{DoxyEnumerate}
\item The values of  {\ttfamily owns},  {\ttfamily len} and {\ttfamily max\+\_\+len} properties for the two collections must be identical. Otherwise read/take will fail with \doxylink{group__DDSReturnTypesModule_gga73f148aaf96b5f6f9fc630b7cfeb0c91a3a638871d5b4174c32c8d2880f1f6770}{DDS\+\_\+\+RETCODE\+\_\+\+PRECONDITION\+\_\+\+NOT\+\_\+\+MET}. 


\item On successful output, the values of  {\ttfamily owns},  {\ttfamily len} and {\ttfamily max\+\_\+len} will be the same for both collections. 


\item If the initial {\ttfamily max\+\_\+len==0}, then the {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+seq} collections will be filled with elements that are loaned by the \doxylink{classDDSDataReader}{DDSData\+Reader}. On output,  {\ttfamily owns} will be FALSE,  {\ttfamily len} will be set to the number of values returned, and {\ttfamily max\+\_\+len} will be set to a value verifying {\ttfamily max\+\_\+len} \texorpdfstring{$>$}{>}= {\ttfamily len}. The use of this variant allows for zero-\/copy access to the data and the application will need to return the loan to the \doxylink{classDDSDataReader}{DDSData\+Reader} using \doxylink{structFooDataReader_ad9ef915c38563e3a06e1ec8f8287730a}{Foo\+Data\+Reader\+::return\+\_\+loan}. 


\item If the initial {\ttfamily max\+\_\+len\texorpdfstring{$>$}{>}0}  and {\ttfamily owns==FALSE},  then the read or take operation will fail with \doxylink{group__DDSReturnTypesModule_gga73f148aaf96b5f6f9fc630b7cfeb0c91a3a638871d5b4174c32c8d2880f1f6770}{DDS\+\_\+\+RETCODE\+\_\+\+PRECONDITION\+\_\+\+NOT\+\_\+\+MET}. This avoids the potential hard-\/to-\/detect memory leaks caused by an application forgetting to return the loan. 


\item If initial {\ttfamily max\+\_\+len\texorpdfstring{$>$}{>}0}  and {\ttfamily owns==TRUE},  then the read or take operation will copy the {\ttfamily received\+\_\+data} values and \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} values into the elements already inside the collections. On output,  {\ttfamily owns} will be TRUE,  {\ttfamily len} will be set to the number of values copied and {\ttfamily max\+\_\+len} will remain unchanged. The use of this variant forces a copy but the application can control where the copy is placed and the application will not need to return the loan. The number of samples copied depends on the relative values of {\ttfamily max\+\_\+len} and {\ttfamily max\+\_\+samples\+:} 


\begin{DoxyItemize}
\item If {\ttfamily max\+\_\+samples} == LENGTH\+\_\+\+UNLIMITED, then at most {\ttfamily max\+\_\+len} values will be copied. The use of this variant lets the application limit the number of samples returned to what the sequence can accommodate. 


\item If {\ttfamily max\+\_\+samples} \texorpdfstring{$<$}{<}= {\ttfamily max\+\_\+len}, then at most {\ttfamily max\+\_\+samples} values will be copied. The use of this variant lets the application limit the number of samples returned to fewer that what the sequence can accommodate.  


\item If {\ttfamily max\+\_\+samples} \texorpdfstring{$>$}{>} {\ttfamily max\+\_\+len}, then the read or take operation will fail with \doxylink{group__DDSReturnTypesModule_gga73f148aaf96b5f6f9fc630b7cfeb0c91a3a638871d5b4174c32c8d2880f1f6770}{DDS\+\_\+\+RETCODE\+\_\+\+PRECONDITION\+\_\+\+NOT\+\_\+\+MET}. This avoids the potential confusion where the application expects to be able to access up to {\ttfamily max\+\_\+samples}, but that number can never be returned, even if they are available in the \doxylink{classDDSDataReader}{DDSData\+Reader}, because the output sequence cannot accommodate them. 
\end{DoxyItemize}
\end{DoxyEnumerate}

As described above, upon completion, the {\ttfamily received\+\_\+data} and {\ttfamily info\+\_\+seq} collections may contain elements loaned from the \doxylink{classDDSDataReader}{DDSData\+Reader}. If this is the case, the application will need to use \doxylink{structFooDataReader_ad9ef915c38563e3a06e1ec8f8287730a}{Foo\+Data\+Reader\+::return\+\_\+loan} to return the loan once it is no longer using the {\ttfamily received\+\_\+data} in the collection. When \doxylink{structFooDataReader_ad9ef915c38563e3a06e1ec8f8287730a}{Foo\+Data\+Reader\+::return\+\_\+loan} completes, the collection will have  {\ttfamily owns=FALSE} and  {\ttfamily max\+\_\+len=0}. The application can determine whether it is necessary to return the loan or not based on how the state of the collections when the read/take operation was called  or by accessing the {\ttfamily owns} property.  However, in many cases it may be simpler to always call \doxylink{structFooDataReader_ad9ef915c38563e3a06e1ec8f8287730a}{Foo\+Data\+Reader\+::return\+\_\+loan}, as this operation is harmless (i.\+e., it leaves all elements unchanged) if the collection does not have a loan. 

To avoid potential memory leaks, the implementation of the Foo and \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} collections should disallow changing the length of a collection for which {\ttfamily owns==FALSE}. Furthermore, deleting a collection for which {\ttfamily owns==FALSE} should be considered an error.  

On output, the collection of Foo values and the collection of \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} structures are of the same length and are in a one-\/to-\/one correspondence. Each \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} provides information, such as the source\+\_\+timestamp, the sample\+\_\+state, view\+\_\+state, and instance\+\_\+state, etc., about the corresponding sample. 

Some elements in the returned collection may not have valid data. If the instance\+\_\+state in the \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} is \doxylink{group__DDSInstanceStateModule_ggaf2264cae1aa8cd66490debfdc5e0c360a51e7b0651e135e656327002e41787dbf}{DDS\+\_\+\+NOT\+\_\+\+ALIVE\+\_\+\+DISPOSED\+\_\+\+INSTANCE\+\_\+\+STATE} or \doxylink{group__DDSInstanceStateModule_ggaf2264cae1aa8cd66490debfdc5e0c360a72ebdc6f53c9a7588458b48e3ea66507}{DDS\+\_\+\+NOT\+\_\+\+ALIVE\+\_\+\+NO\+\_\+\+WRITERS\+\_\+\+INSTANCE\+\_\+\+STATE}, then the last sample for that instance in the collection (that is, the one whose \doxylink{structDDS__SampleInfo}{DDS\+\_\+\+Sample\+Info} has sample\+\_\+rank==0) does not contain valid data. 

Samples that contain no data do not count towards the limits imposed by the \doxylink{structDDS__ResourceLimitsQosPolicy}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy}. The act of reading/taking a sample sets its sample\+\_\+state to \doxylink{group__DDSSampleStateModule_ggadb6d36e7c796da27519b6bf7f8f187e5a4435d5fd0a36806ebd1c67210345a70b}{DDS\+\_\+\+READ\+\_\+\+SAMPLE\+\_\+\+STATE}. 

If the sample belongs to the most recent generation of the instance, it will also set the view\+\_\+state of the instance to \doxylink{group__DDSViewStateModule_ggab7a8a4ae44a2c00f411a4461135b45f1ad0a3502068e5e66e20a873a0aaa881be}{DDS\+\_\+\+NOT\+\_\+\+NEW\+\_\+\+VIEW\+\_\+\+STATE}. When a sample is received via Zero Copy transfer over shared memory, the sample can be reused by the Data\+Writer once it is removed from the Data\+Writer\textquotesingle{}s send queue. Since there is no synchronization between the Data\+Reader and the Data\+Writer, the sample could be overwritten by the Data\+Writer before it is processed by the Data\+Reader. The \doxylink{structFooDataReader_ab14ac46cc38d0ff25543a02c0a09fcfb}{Foo\+Data\+Reader\+::is\+\_\+data\+\_\+consistent} operation can be used after processing the sample to check if it was overwritten by the Data\+Writer. 

A precondition for using this operation is to set \doxylink{structDDS__DataWriterShmemRefTransferModeSettings_af4766de78ad7d0787d1c073576c0eae4}{DDS\+\_\+\+Data\+Writer\+Shmem\+Ref\+Transfer\+Mode\+Settings\+::enable\+\_\+data\+\_\+consistency\+\_\+check} to true.
