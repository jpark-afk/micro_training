APIs (C or Traditional C++)
===========================

.. Release Notes from this point.

:major:`[Major]` Undefined DDS_TIME_INVALID variables
-----------------------------------------------------
``DDS_TIME_INVALID`` and related variables were declared and documented, but
not defined; when used, they caused linking errors.

[RTI Issue ID MICRO-6222]

:major:`[Major]` Setting large max sequence size would produce integer overflow
-------------------------------------------------------------------------------
Calling ``seq_set_maximum`` with a very large value would overflow and
result in a smaller-than-expected memory allocation.

[RTI Issue ID MICRO-12766]

:minor:`[Minor]` Low resolution timestamps could cause Zero Copy samples to remain visible longer than expected
---------------------------------------------------------------------------------------------------------------
While using the Zero Copy v2 transport, if a sample was pushed out of a
*DataWriter*'s history at the same time (with the same timestamp) as a
*DataReader* was created, the *DataReader* would still be able to
observe it. Additionally, Zero Copy samples with timestamps using a
different clock than the *DataReader* could be missed.

[RTI Issue ID MICRO-10926]

:minor:`[Minor]` DDS_Entity_get_entity_kind was declared and documented but not defined
---------------------------------------------------------------------------------------
The function of the public API ``DDS_Entity_get_entity_kind`` was
declared and documented but not defined. It could cause linking errors
when used.

[RTI Issue ID MICRO-9226]

:trivial:`[Trivial]` False positive error messages when reattaching a condition to a WaitSet
--------------------------------------------------------------------------------------------
If an error condition was attached to the same
:link_connextmicro_dds_api_c_up_two:`WaitSet <group__DDSConditionsModule.html>`
more than once, |me| would log a false-positive error message.

[RTI Issue ID MICRO-2857]
