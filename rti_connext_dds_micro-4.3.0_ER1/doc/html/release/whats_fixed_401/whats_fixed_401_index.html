10.5.6. What’s Fixed in 4.0.1¶

The following are fixes since Connext Micro 4.0.0.

[Critical]: System-stopping issue, such as a crash or data loss.
[Major]: Significant issue with no easy workaround.
[Minor]: Issue that usually has a workaround.
[Trivial]: Small issue, such as a typo in a log.

  • 10.5.6.1. Discovery
    • 10.5.6.1.1. [Trivial] Possible error message during discovery with Connext Professional
  • 10.5.6.2. Usability
    • 10.5.6.2.1. [Minor] rtiddsgen failed to run if the default shell was not bash compatible
    • 10.5.6.2.2. [Trivial] Self toolchain file missing from the Connext Micro bundle
    • 10.5.6.2.3. [Trivial] Empty README.txt generated for an example
  • 10.5.6.3. APIs (C or Traditional C++)
    • 10.5.6.3.1. [Minor] Unexpected behavior when copying a DDS_UnsignedShortSeq with 0 length
    • 10.5.6.3.2. [Minor] Missing C++ APIs for discovery operations
    • 10.5.6.3.3. [Trivial] C++ examples used the undocumented get_reference API
  • 10.5.6.4. Generated Code (C, Traditional C++, and Modern C++)
    • 10.5.6.4.1. [Major] Incorrect generated code when using IDL whose name starts with a number
    • 10.5.6.4.2. [Major] Code generated for a FLAT_DATA type failed to compile when using namespace option
    • 10.5.6.4.3. [Major] Code generated for an aliased sequence of an aliased string failed to compile
  • 10.5.6.5. Crashes
    • 10.5.6.5.1. [Minor] Potential segmentation fault while creating entities
  • 10.5.6.6. Data Corruption
    • 10.5.6.6.1. [Critical] DataReader on a Topic with appendable type could receive samples with incorrect value
    • 10.5.6.6.2. [Critical] Undefined behavior using XCDR2 with keyed topic types with key union members
    • 10.5.6.6.3. [Critical] Incorrect keyhash generated when receiving data without a keyhash from a node with different endianness
  • 10.5.6.7. Interoperability
    • 10.5.6.7.1. [Major] Incorrect deserialization of CDR encapsulation padding bit
