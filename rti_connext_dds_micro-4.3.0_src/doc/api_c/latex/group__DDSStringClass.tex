\doxysubsubsubsubsection{Detailed Description}
String creation, cloning, assignment, and deletion. 

The functions in this class ensure consistent cross-\/platform implementations for string creation (\doxylink{group__DDSStringClass_gaf3b22138dd2db7f1f2a2445d671b9046}{DDS\+\_\+\+String\+\_\+alloc()}), deletion (\doxylink{group__DDSStringClass_ga13074f0132f743923a4a36ee533997fe}{DDS\+\_\+\+String\+\_\+free()}), and cloning (\doxylink{group__DDSStringClass_gaab34d3575bf66cd95a890f7e21eb697a}{DDS\+\_\+\+String\+\_\+dup()}) that preserve the mutable value type semantics. These are to be viewed as functions that define a {\ttfamily string} class whose data is represented by a {\ttfamily \textquotesingle{}char\texorpdfstring{$\ast$}{*}\textquotesingle{}}.\hypertarget{group__DDSStringClass_DDSStringClass_conventions}{}\doxysubsubsubsubsection{\texorpdfstring{Conventions}{Conventions}}\label{group__DDSStringClass_DDSStringClass_conventions}
The following conventions govern the memory management of strings in RTI Connext DDS Micro.


\begin{DoxyItemize}
\item The DDS implementation ensures that when value types containing strings are passed back and forth to the DDS APIs, the strings are created/deleted/assigned/cloned using the {\ttfamily string} class functions. 
\begin{DoxyItemize}
\item Value types containing strings have ownership of the contained string. Thus, when a value type is deleted, the contained string field is also deleted. 
\end{DoxyItemize}
\item The user must ensure that when value types containing strings are passed back and forth to the DDS APIs, the strings are created/deleted/assigned/cloned using the String class functions.  
\end{DoxyItemize}

The representation of a string in C/\+C++ unfortunately does not allow programs to detect how much memory has been allocated for a string. RTI Connext DDS Micro must therefore make some assumptions when a user requests that a string be copied into. The following rules apply when RTI Connext DDS Micro is copying into a string or string sequence\+:

\begin{DoxyItemize}
\item If the \textquotesingle{}char\texorpdfstring{$\ast$}{*}\textquotesingle{} is NULL, RTI Connext DDS Micro will log a warning and allocate a new string on behalf of the user. {\itshape To avoid leaking memory, you must ensure that the string will be freed (see \doxysectlink{group__DDSStringClass_DDSStringClass_usage}{Usage}{1} below)}. \item If the \textquotesingle{}char\texorpdfstring{$\ast$}{*}\textquotesingle{} is not NULL, RTI Connext DDS Micro will assume that you are managing the string\textquotesingle{}s memory yourself and have allocated enough memory to store the string to be copied. {\itshape RTI Connext DDS Micro will copy into your memory; to avoid memory corruption, be sure to allocate enough of it.} Also, {\itshape do not pass structures containing junk pointers into RTI Connext DDS Micro}; you are likely to crash.\end{DoxyItemize}
\hypertarget{group__DDSStringClass_DDSStringClass_usage}{}\doxysubsubsubsubsection{\texorpdfstring{Usage}{Usage}}\label{group__DDSStringClass_DDSStringClass_usage}
This requirement can generally be assured by adhering to the following {\itshape idiom} for manipulating strings.


\begin{DoxyCode}{0}
\DoxyCodeLine{Always\ use}
\DoxyCodeLine{\ \ \ \ \ \mbox{\hyperlink{group__DDSStringClass_gaf3b22138dd2db7f1f2a2445d671b9046}{DDS\_String\_alloc}}()\ to\ create,}
\DoxyCodeLine{\ \ \ \ \ \mbox{\hyperlink{group__DDSStringClass_gaab34d3575bf66cd95a890f7e21eb697a}{DDS\_String\_dup}}()\ to\ clone,}
\DoxyCodeLine{\ \ \ \ \ \mbox{\hyperlink{group__DDSStringClass_ga13074f0132f743923a4a36ee533997fe}{DDS\_String\_free}}()\ to\ delete}
\DoxyCodeLine{\ a\ \textcolor{keywordtype}{string}\ '\textcolor{keywordtype}{char}*'\ that\ is\ passed\ back\ and\ forth\ between}
\DoxyCodeLine{\ user\ code\ and\ the\ DDS\ C/C++\ APIs.}

\end{DoxyCode}


Not adhering to this idiom can result in bad pointers, and incorrect memory being freed.

In addition, the user code should be vigilant to avoid memory leaks. It is good practice to\+:

\begin{DoxyItemize}
\item Balance occurrences of \doxylink{group__DDSStringClass_gaf3b22138dd2db7f1f2a2445d671b9046}{DDS\+\_\+\+String\+\_\+alloc()}, \doxylink{group__DDSStringClass_gaab34d3575bf66cd95a890f7e21eb697a}{DDS\+\_\+\+String\+\_\+dup()}, with matching occurrences of \doxylink{group__DDSStringClass_ga13074f0132f743923a4a36ee533997fe}{DDS\+\_\+\+String\+\_\+free()} in the code. \item Finalize value types containing strings. In C++ the destructor accomplishes this automatically. in C, explicit "{}destructor"{} functions are provided; these functions are typically called "{}finalize."{} \end{DoxyItemize}
