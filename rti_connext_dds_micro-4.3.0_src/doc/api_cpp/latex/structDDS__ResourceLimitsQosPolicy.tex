\hypertarget{structDDS__ResourceLimitsQosPolicy_DDSResourceLimitsQosModule_usage}{}\doxysubsubsection{\texorpdfstring{Usage}{Usage}}\label{structDDS__ResourceLimitsQosPolicy_DDSResourceLimitsQosModule_usage}
This policy controls the resources that RTI Connext DDS Micro can use in order to meet the requirements imposed by the application and other QoS settings. 

If \doxylink{classDDSDataWriter}{DDSData\+Writer} objects are communicating samples faster than they are ultimately taken by the \doxylink{classDDSDataReader}{DDSData\+Reader} objects, the middleware will eventually hit against some of the Qo\+S-\/imposed resource limits. Note that this may occur when just a single \doxylink{classDDSDataReader}{DDSData\+Reader} cannot keep up with its corresponding \doxylink{classDDSDataWriter}{DDSData\+Writer}. The behavior in this case depends on the setting for the \doxylink{group__DDSReliabilityQosModule}{RELIABILITY}. If reliability is \doxylink{group__DDSReliabilityQosModule_ggaf09e82d431c2328186c7fb4b3fa9ad91aae82431f2015239328733f3cb41d780d}{DDS\+\_\+\+BEST\+\_\+\+EFFORT\+\_\+\+RELIABILITY\+\_\+\+QOS} then RTI Connext DDS Micro is allowed to drop samples. If the reliability is \doxylink{group__DDSReliabilityQosModule_ggaf09e82d431c2328186c7fb4b3fa9ad91ae5d04022c6405f9db6406489956d1923}{DDS\+\_\+\+RELIABLE\+\_\+\+RELIABILITY\+\_\+\+QOS}, RTI Connext DDS Micro will block the \doxylink{classDDSDataWriter}{DDSData\+Writer} or discard the sample at the \doxylink{classDDSDataReader}{DDSData\+Reader} in order not to lose existing samples.

Represents the maximum samples the middleware can store for any one \doxylink{classDDSDataWriter}{DDSData\+Writer} or \doxylink{classDDSDataReader}{DDSData\+Reader}. 

Specifies the maximum number of data samples a \doxylink{classDDSDataWriter}{DDSData\+Writer} or \doxylink{classDDSDataReader}{DDSData\+Reader} can manage across all the instances associated with it. 

For unkeyed types this value has to be equal to max\+\_\+samples\+\_\+per\+\_\+instance. 

\doxylink{classDDSDataReader}{DDSData\+Reader} 

The \doxylink{structDDS__ResourceLimitsQosPolicy_a90db906a3958146c5e22557db648e7ff}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy\+::max\+\_\+samples} resource limit limits the maximum number of samples a \doxylink{classDDSDataReader}{DDSData\+Reader} can allocate and cache. Samples are cached before they are made available to the application; for example, when samples are received out of order. Thus, this resource limit may impact throughput and latency. 

What this value should be set to is determined by a number of factors\+: \begin{DoxyItemize}
\item For best effort, it can be set to 1 since samples are not cached. However, if data is polled or samples are loaned longer than the update frequency, this resource-\/limit should be increased to prevent samples from being reused before the application has a chance to access the data (along with \doxylink{structDDS__HistoryQosPolicy_aef0fb3fd3579866be17d1a936f5e3729}{DDS\+\_\+\+History\+Qos\+Policy\+::depth}). \item For reliable data, the value should take into account the data rate, the heartbeat rate of the \doxylink{classDDSDataWriter}{DDSData\+Writer}, and the number of piggybacked heartbeats. \end{DoxyItemize}


\doxylink{classDDSDataWriter}{DDSData\+Writer} 

The \doxylink{structDDS__ResourceLimitsQosPolicy_a90db906a3958146c5e22557db648e7ff}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy\+::max\+\_\+samples} resource limit limits the maximum number of samples a \doxylink{classDDSDataWriter}{DDSData\+Writer} can allocate and maintain state for at any given time. Every time a write operation is called, a sample is allocated from the cache and filled in with user data. 

A sample allocated from the pool controlled by this resource limit can be reused based on the following rules\+: \begin{DoxyItemize}
\item If the \doxylink{classDDSDataWriter}{DDSData\+Writer} is using \doxylink{group__DDSReliabilityQosModule_ggaf09e82d431c2328186c7fb4b3fa9ad91aae82431f2015239328733f3cb41d780d}{DDS\+\_\+\+BEST\+\_\+\+EFFORT\+\_\+\+RELIABILITY\+\_\+\+QOS} effort, the sample is returned for reuse after the transport returns from the write call. \item If the \doxylink{classDDSDataWriter}{DDSData\+Writer} is using \doxylink{group__DDSReliabilityQosModule_ggaf09e82d431c2328186c7fb4b3fa9ad91ae5d04022c6405f9db6406489956d1923}{DDS\+\_\+\+RELIABLE\+\_\+\+RELIABILITY\+\_\+\+QOS} and \doxylink{group__DurabilityQosPolicyModule_gga4bc6b72c72928cb9ed6432e3e6a83e2eab81cc94a7a319b48b17e177d217a09d4}{DDS\+\_\+\+VOLATILE\+\_\+\+DURABILITY\+\_\+\+QOS}, the sample is returned when all known \doxylink{classDDSDataReader}{DDSData\+Reader} entities have acknowledged the sample or the \doxylink{classDDSDataWriter}{DDSData\+Writer} has given up on delivering the sample, controlled by \doxylink{structDDS__RtpsReliableWriterProtocol__t_a5be67d978618b5995cb517b51231d39d}{DDS\+\_\+\+Rtps\+Reliable\+Writer\+Protocol\+\_\+t\+::max\+\_\+heartbeat\+\_\+retries}, whichever happens first. \item If the \doxylink{classDDSDataWriter}{DDSData\+Writer} is using \doxylink{group__DDSReliabilityQosModule_ggaf09e82d431c2328186c7fb4b3fa9ad91ae5d04022c6405f9db6406489956d1923}{DDS\+\_\+\+RELIABLE\+\_\+\+RELIABILITY\+\_\+\+QOS} and not using \doxylink{group__DurabilityQosPolicyModule_gga4bc6b72c72928cb9ed6432e3e6a83e2eab81cc94a7a319b48b17e177d217a09d4}{DDS\+\_\+\+VOLATILE\+\_\+\+DURABILITY\+\_\+\+QOS}, the sample is returned to the pool for reuse only if the history depth is exceeded and the \doxylink{structDDS__HistoryQosPolicy_a3cb2743cd13a81614bcc4f314cd640ab}{DDS\+\_\+\+History\+Qos\+Policy\+::kind} is set to \doxylink{group__DDSHistoryQosModule_gga96c54dadb2beb87b23776e766e282185a993d3120b7bbb347ce11e0e6f68b29ff}{DDS\+\_\+\+KEEP\+\_\+\+LAST\+\_\+\+HISTORY\+\_\+\+QOS}. \end{DoxyItemize}
For best effort communication, this resource limit can be set to 1. 

For reliable communication, the value of this resource limit determines the maximum number of samples a \doxylink{classDDSDataWriter}{DDSData\+Writer} can keep in unacknowledged state before reusing potentially unacknowledged samples for \doxylink{group__DDSHistoryQosModule_gga96c54dadb2beb87b23776e766e282185a993d3120b7bbb347ce11e0e6f68b29ff}{DDS\+\_\+\+KEEP\+\_\+\+LAST\+\_\+\+HISTORY\+\_\+\+QOS}. The max\+\_\+instance resource-\/limit limits the maximum number of instances a \doxylink{classDDSDataReader}{DDSData\+Reader} can manage. Instance state is one of the most expensive resources to maintain, as well as often being the highest one. 

The resources allocated by an instance are normally only released when an instance is disposed {\itshape and} all known owners have unregistered the instance; please refer to \doxylink{structFooDataWriter_a8fc58aea4e8ff79758fe2b8fedf8670c}{Foo\+Data\+Writer\+::unregister\+\_\+instance} and \doxylink{structFooDataWriter_a82698123a576af876c614ea3d2ce5cc5}{Foo\+Data\+Writer\+::dispose}.

When the \doxylink{structDDS__DataReaderResourceLimitsQosPolicy_ac29b5e108cb7850f99662b74cdb36d58}{DDS\+\_\+\+Data\+Reader\+Resource\+Limits\+Qos\+Policy\+::instance\+\_\+replacement} policy is set to replace the oldest instance, \doxylink{group__DDSDataReaderResourceLimitsQosModule_ggaf9e17bc2037d1bcb2f100526364afe14a53d930a5bacfc51b0708c1f47a291165}{DDS\+\_\+\+REPLACE\+\_\+\+OLDEST\+\_\+\+INSTANCE\+\_\+\+REPLACEMENT\+\_\+\+QOS}, information about the oldest instance is automatically removed and the newly discovered instance is received. \doxylink{classDDSDataReader}{DDSData\+Reader} 

This resource limit limits the maximum number of samples that can be cached for a single instance; it must be less than or equal to max\+\_\+samples and greater or equal to the history depth. When \doxylink{structDDS__ResourceLimitsQosPolicy_ae3d9339bebf4c7163cf6dff82882cbef}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy\+::max\+\_\+samples\+\_\+per\+\_\+instance} is higher than depth, it makes it possible to loan samples and receive up to depth samples before returning loaned samples. 

When this resource-\/limit or \doxylink{structDDS__HistoryQosPolicy_aef0fb3fd3579866be17d1a936f5e3729}{DDS\+\_\+\+History\+Qos\+Policy\+::depth} is exceeded and the \doxylink{structDDS__HistoryQosPolicy_a3cb2743cd13a81614bcc4f314cd640ab}{DDS\+\_\+\+History\+Qos\+Policy\+::kind} is \doxylink{group__DDSHistoryQosModule_gga96c54dadb2beb87b23776e766e282185a993d3120b7bbb347ce11e0e6f68b29ff}{DDS\+\_\+\+KEEP\+\_\+\+LAST\+\_\+\+HISTORY\+\_\+\+QOS}, the oldest sample is removed from the cache. 

Note that it is possible to exceed the {\ttfamily max\+\_\+samples\+\_\+per\+\_\+instance} limit while samples are being received and processed, but before they are added to the reader queue. This typically happens when there are holes in the sequence numbers that must be filled before the samples can be committed to the reader queue. If a sample cannot be committed due to the {\ttfamily max\+\_\+samples\+\_\+per\+\_\+instance} limit, it is {\ttfamily not} dropped. Instead, it is recommitted when space is made available, such as the application taking samples from the reader queue or older samples being removed due to KEEP\+\_\+\+LAST. 

For unkeyed types this value has to be equal to max\+\_\+samples. 

\doxylink{classDDSDataWriter}{DDSData\+Writer} 

This resource limit limits the maximum number of samples that can be cached for a single instance; it must be less than or equal to max\+\_\+samples and greater or equal to the \doxylink{structDDS__HistoryQosPolicy_aef0fb3fd3579866be17d1a936f5e3729}{DDS\+\_\+\+History\+Qos\+Policy\+::depth}. 

\doxylink{structDDS__HistoryQosPolicy_aef0fb3fd3579866be17d1a936f5e3729}{DDS\+\_\+\+History\+Qos\+Policy\+::depth} determines how many samples are kept in case of \doxylink{group__DurabilityQosPolicyModule_gga4bc6b72c72928cb9ed6432e3e6a83e2ea82f8bcc308fa4721d8d8525c383e7d25}{DDS\+\_\+\+TRANSIENT\+\_\+\+LOCAL\+\_\+\+DURABILITY\+\_\+\+QOS} durability and made available to late joining \doxylink{classDDSDataReader}{DDSData\+Reader}, while \doxylink{structDDS__ResourceLimitsQosPolicy_ae3d9339bebf4c7163cf6dff82882cbef}{DDS\+\_\+\+Resource\+Limits\+Qos\+Policy\+::max\+\_\+samples\+\_\+per\+\_\+instance} is the maximum number of {\itshape unacknowledged} samples the \doxylink{classDDSDataWriter}{DDSData\+Writer} can keep per instance. Thus, if max\+\_\+samples\+\_\+per\+\_\+instance \texorpdfstring{$>$}{>} depth, it is possible to keep additional unacknowledged samples.
